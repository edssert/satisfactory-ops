# 외부 데이터 해석은 주장이다

원본에서 값을 꺼내 "이건 X를 뜻한다"고 말하는 순간, 그것은 데이터가 아니라 **주장**이다.
주장에는 독립 근거가 필요하다. 이 스킬은 그 근거를 찾는 절차다.

## 이 스킬이 존재하는 이유 — 실제로 난 사고 둘

**① 있는 것을 주운 것으로 읽었다.** 세이브에 들어 있는 수집품 액터를 "주운 것"으로 셌다.
그건 주운 것이 아니라 **지나간 지역에 아직 놓여 있는 것**이었다. 36시간 세이브에서
액터는 228개, 실제로 주운 것은 14개. **16배**를 틀렸다. 진짜 목록은 레벨마다 따로 있는
`collectables` 였다. 창고 재고와 한 번만 대조했으면 그 자리에서 드러났을 문제다.

**② 이름이 같으니 뜻도 같다고 읽었다.** `mSpeed` 는 컨베이어에서만 처리량이다. 그런데
작업자용 엘리베이터(`FGBuildableElevator`)에도 같은 이름의 필드가 있고 값이 800이다.
그게 400/분짜리 벨트로 새어 나가 화면이 **"그때 필요한 벨트: 작업자용 엘리베이터"**라고
답했다. 필드 이름은 그 필드의 소유자를 말해 주지 않는다.

두 사고의 공통점: **원본 안에서만 확인했다.** 원본은 자기 자신과 늘 일치한다.
그래서 원본만으로는 해석이 틀렸는지 절대 알 수 없다.

---

## 절차 (다섯 단계, 건너뛰지 않는다)

### 1. 주장을 한 문장으로 적는다

머릿속에 두면 검증할 수 없다. 이 형식으로 적는다:

> `<원본의 무엇>` 의 `<값>` 은 `<앱에서 뜻하는 것>` 을 뜻한다. 근거는 `<무엇>` 이다.

나쁜 예: "세이브에서 수집품을 읽는다"
좋은 예: "Persistent_Level 의 수집품 typePath 액터 하나 = 플레이어가 주운 것 하나. 근거는
액터가 존재한다는 사실이다"

이렇게 적으면 ②의 "근거는 액터가 존재한다는 사실"이 이미 수상해 보인다.
**존재는 상태가 아니다.** 그게 사고 ①의 전부였다.

### 2. 반증 표본을 먼저 정한다

"이 해석이 틀렸다면 어디서 제일 먼저 어긋나겠는가?" 를 적는다. 대조하기 **전에** 적어야
한다. 나중에 적으면 나온 값에 맞춰 기준을 고치게 된다.

| 해석의 모양 | 어디서 어긋나는가 |
|---|---|
| "이 목록에 있으면 = 했다" | 반대쪽 목록(안 한 것)과 합쳐서 **총량**이 되는가 |
| "이 필드가 = 처리량이다" | 이 필드를 가진 **다른 클래스**들이 말이 되는 값인가 |
| "이 수치가 = 분당 산출이다" | 게임 안 표시값·위키 표와 **한 자릿수** 안에 있는가 |
| "이 좌표계가 = 맵 좌표다" | 이미 검증된 다른 데이터셋(자원 노드)으로 **역산**하면 맞는가 |

### 3. 독립 대조원을 찾는다 — 최소 하나

**독립**이란 같은 파일의 다른 필드가 아니라 **다른 계층**에서 온 것을 말한다.

| 사다리 | 대조원 | 예 |
|---|---|---|
| 1 | **게임이 스스로 센 값** | 창고·인벤토리 재고, 통계 화면, 잠금 해제 목록 |
| 2 | **고정 총량** | 맵에 놓인 슬러그·소머슬룹·하드 드라이브의 전체 개수 (위키) |
| 3 | **공식 위키의 표** | 벨트 등급별 처리량, 기계 전력 |
| 4 | **이미 검증된 우리 데이터** | `src/data/app/resource-nodes.json` 626개로 좌표계 역산 |
| 5 | **사용자에게 물어보기** | 게임 화면을 열어 숫자를 읽어 달라고 한다. 부끄러운 일이 아니다 |

실제로 ①을 잡은 것은 사다리 1이었다: 파란 슬러그를 8개 주웠다고 나왔고, 창고에 5개 +
동력 조각 1개가 있었다. 앞뒤가 맞았다. 228이었다면 창고가 설명을 못 한다.

**대조원을 못 찾으면 그 해석은 앱에 넣지 않는다.** `docs/research/` 의 "미해결"에만 적는다.
CLAUDE.md 의 confidence 등급으로는 `unsourced` 다.

### 4. 자릿수를 먼저 본다

정밀 대조 전에 크기부터 본다. 사고 ①은 16배, 사고 ②는 6.7배였다. 둘 다 **자릿수에서**
드러난다. 소수점 둘째 자리를 맞추기 전에 이것부터 물어라:

- 이 게임에서 이 값의 **이론상 최대**는 얼마인가? (맵의 슬러그는 유한하다)
- 그 최대를 넘었는가? 넘었으면 해석이 틀린 것이다. 데이터가 틀린 게 아니다
- 36시간 플레이에서 나올 법한 수인가? 사람이 228개를 줍고 창고가 비어 있을 수 있는가

### 5. 통과한 해석을 회귀로 잠근다

검증은 한 번 하면 썩는다. 다음 패치·다음 세이브에 다시 깨진다. **이 저장소에는 잠글
자리가 세 곳** 있고, 어느 것을 쓸지는 데이터가 어디서 오느냐로 정해진다:

| 데이터 출처 | 잠그는 자리 | 어떻게 |
|---|---|---|
| 게임 원본(Docs.json) | `scripts/build-data.mjs` 의 새니티 표 | 조건 한 줄 추가. 실패하면 파일을 안 쓰고 죽는다 |
| 앱 데이터 가공 | `scripts/build-app-data.mjs` | 같은 방식. `npm run data:check` 로 확인 |
| 세이브 파싱 | `scripts/test-checkup.mjs` 의 `GOLD` | 실제 세이브에서 찍은 값을 박아 둔다 |
| 브라우저 동작 | `scripts/test-save-import.mjs` | 상한·불변식. ①은 `> 200` 상한으로 잠갔다 |

잠글 때는 **값 하나가 아니라 불변식**을 적어라.

```js
// 나쁨 — 세이브를 바꾸면 그냥 깨진다
['주운 수집품 14건', collected === 14],

// 좋음 — 해석이 틀리면 깨지고, 세이브가 바뀌어도 안 깨진다
['주운 것이 맵 전체 수집품 수를 넘지 않는다', collected <= totalOnMap],
['주운 것 중 창고에 남은 몫이 설명된다', collected >= inStorage],
```

②의 잠금은 이미 `build-data.mjs` 에 들어 있다 —
`['처리량이 붙은 건물은 컨베이어뿐', ...]`. 이런 모양을 따라 쓴다.

## 필드를 쓰기 전에 소유자를 센다

원본 필드를 새로 쓸 때는 **매번** 이것부터 돌린다. 30초 걸린다.

```bash
node .claude/skills/external-data-claim/scripts/field-scope.mjs mSpeed
node .claude/skills/external-data-claim/scripts/field-scope.mjs beltItemsPerMinute --gen
```

`--gen` 은 원본 대신 생성물(`src/data/buildings.json`)을 본다. 필터가 새는지 볼 때 쓴다.

읽는 법:

- **소유자가 하나** → 그대로 써도 된다 (종료 코드 0)
- **소유자가 둘 이상** → 값의 뜻이 클래스마다 같은지 **확인해야 한다** (종료 코드 3).
  같으면 그대로, 다르면 `nativeClass` 로 거르고 새니티 표에 검사를 추가한다.
  벨트와 리프트는 같은 뜻이라 둘 다 쓴다. 엘리베이터는 다른 뜻이라 뺀다

종료 코드 3은 "틀렸다"가 아니라 "네가 아직 안 본 소유자가 있다"는 뜻이다.

## 반려 기준 — 하나라도 걸리면 화면에 내지 않는다

- [ ] 주장을 한 문장으로 적었는가 (§1 형식)
- [ ] 근거가 "그 자리에 있다"는 **존재**뿐인가 → 반려. 존재는 상태가 아니다
- [ ] 원본 **바깥**의 대조원이 하나라도 있는가 → 없으면 반려
- [ ] 자릿수 검사를 통과했는가 (게임의 이론상 최대를 넘지 않는가)
- [ ] 새로 쓰는 원본 필드에 `field-scope.mjs` 를 돌렸는가
- [ ] 통과한 해석을 회귀 검사로 잠갔는가. 그 검사를 **일부러 깨뜨려** 정말 죽는지 봤는가
- [ ] 대조에 실패한 해석을 "대략 맞는다"로 넘기지 않았는가

## 화면에 낼 때

CLAUDE.md 의 등급을 그대로 쓴다. 대조원 개수가 등급을 정한다.

- 원본에서 생성 + 대조 통과 → `verified`
- 원본에 없고 커뮤니티 출처 둘 이상 일치 → `consensus`, 화면에 "커뮤니티 합의" 표기
- 출처가 갈림 → `disputed`, 양쪽 다 노출
- 대조원 없음 → **앱에 넣지 않는다.** `docs/research/` 의 미해결로만

근거는 `docs/research/<주제>.md` 에 남긴다. 대조에 쓴 값과 그 출처를 같이 적어라 —
다음 사람이 같은 대조를 처음부터 다시 하지 않도록.
