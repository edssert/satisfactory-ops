# 핵심 도메인 반응형 전수 검증

> [!abstract] 판정
> 화면 몇 장을 골라 보는 검사를 홈·가이드·설계·직접 만들기·지도·진단·도감·도구·변경 기록의
> 전수 브라우저 계약으로 확장했다. `scripts/verify-responsive.mjs`가 실제 Chromium에서 9개 도메인을
> 360·390·768·1024·1440·1920·3840px로 렌더한다.

## 자동 판정과 눈 판정을 분리한 이유

기존 `squeeze.mjs`는 폭 48px 미만의 긴 낱말을 눌림 후보로 찾는다. 이 휴리스틱은 `60/분`, `15 MW`처럼
의도적으로 짧은 단위 배지를 오탐할 수 있다. 따라서 완료 게이트는 사용자가 실제로 콘텐츠를 잃는 아래 조건만
자동 실패로 삼고, 밀도·위계·미감은 스크린샷을 직접 열어 판정한다.

- 문서 전체에 가로 스크롤이 생기지 않는다.
- `main`이 뷰포트 좌우 경계를 벗어나지 않는다.
- 각 화면의 `h1`이 충분한 폭과 높이로 보이고 잘림 속성을 쓰지 않는다.
- 런타임 콘솔 오류와 자산 404가 없다.

## 검증 행렬

| 축 | 표본 |
|---|---|
| 도메인 | 홈, 가이드, 설계, 직접 만들기, 지도, 진단, 도감, 도구, 변경 기록 |
| 폭 | 360, 390, 768, 1024, 1440, 1920, 3840px |
| 자동 렌더 | 63개 |
| 수동 픽셀 리뷰 | 390px 핵심 화면, 1440px 편집 화면, 3840px 초광폭 화면 |

## 회귀 잠금

- `npm run test:responsive`는 `npm run verify`의 필수 단계다.
- 새 핵심 도메인을 추가하면 `ROUTES`와 스크린샷 표본을 함께 늘린다.
- 내부 캔버스의 팬·줌 영역은 의도적으로 자기 뷰포트 안에서 움직일 수 있지만 문서 자체를 밀어서는 안 된다.
