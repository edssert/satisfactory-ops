## 요약

**판단은 맞다. 그러나 원인은 "유행을 안 따라서"가 아니다.**

이 저장소의 시각 시스템은 "어두운 유리 계층 + 발광 테두리"로 설계돼 있고 CSS 에도 그렇게 적혀 있다.
그런데 **그 계층을 만드는 토큰 7개가 어디에도 정의되어 있지 않다.** 그래서 브라우저는 관련 선언을
전부 무효로 버린다. 화면에 실제로 남는 것은 검은 배경과 1px 회색 선뿐이다 — `references/ai-tells.md`
가 "이 프로젝트에서 이미 한 번 실패했다"고 기록한 바로 그 상태(`회색 상자와 얇은 선만 남았다`)로
소리 없이 되돌아가 있다.

그 위에, 실제로 낡은 것이 따로 있다. `fx.css` 가 옮겨 온 Magic UI 효과 묶음
(Border Beam · Retro Grid · Shimmer · Gradient Text)과 알약형 뱃지·그라디언트 제목은
2023년 AI 랜딩의 지문 그 자체이고, 2026년 기준으로는 유행을 따른 것이 아니라 **유행이 지나간
자리에 남은 것**이다.

그래서 처방은 둘로 나뉜다: **(A) 죽어 있는 시스템을 되살릴 것, (B) 되살리되 2023년 값이 아니라
2026년 값으로 되살릴 것.** 둘 중 하나만 하면 실패한다. A 만 하면 2023년 랜딩이 되고, B 만 하면
다시 회색 상자가 된다.

## 01. 현재 진단

### 01-1. 결정적 결함 — 시각 시스템이 렌더링되지 않는다

> **조사 중 상태 변화 (2026-08-21)**: 이 조사를 진행하는 동안 다른 작업이 `tokens.css` 에
> 누락 토큰 7개를 정의했다(`--glass: #121926`, `--lit: inset 0 0 0 1px var(--line)`,
> `--ambient-cool: color-mix(...)` 등). 아래 진단은 **그 수정 이전 상태의 실측 기록**이며,
> 캡처와 계산값은 전부 수정 전 빌드 기준이다.
>
> 방향은 이 문서의 P0 권고와 일치한다 — 반투명 유리가 아니라 **불투명 바탕 + 안쪽 1px 링**으로
> 복구했다. 남은 차이 두 가지: (1) `--lit` 이 `--line`(#1f2733, 대비 1.4:1)을 링 색으로 써서
> 어두운 면 위에서 모서리가 거의 안 보인다 — 05-6절은 `#ffffff0a~0f` 같은 **흰색 알파**를
> 권한다(면 색과 무관하게 위쪽 모서리가 살아난다). (2) 얕은 턱(`0 1px 2px`)이 없어 고도가
> 1단뿐이다. 05-6절의 4단 사다리로 확장하는 것이 남은 작업이다.
> 아래 진단은 **왜 그 수정이 필요했는지의 근거 기록**으로 읽으면 된다.

`--glass` · `--glass-blur` · `--glass-sat` · `--lit` · `--lit-strong` · `--ambient-cool` ·
`--ambient-warm` — 이 7개 토큰이 CSS 40여 곳에서 쓰이는데 **`src/` 전체와 빌드 산출물
어디에도 정의가 없다.**

```
$ grep -rn -- "--glass:|--glass-blur:|--lit:|--ambient-cool:" src/     → 0건
$ grep -rho -- "--lit[a-z-]*:[^;}]*" dist/_astro/*.css                 → 0건
```

CSS 커스텀 프로퍼티가 비어 있으면 그 선언은 `IACVT`(invalid at computed-value time)로
처리되어 **속성 전체가 버려진다.** 실제 계산값을 브라우저에서 직접 읽었다
(`.tmp-research/design/probe.mjs`, `/` 화면):

```
var(--glass)      = ""     ← 정의 없음
var(--lit)        = ""
var(--glass-blur) = ""
var(--ambient-cool) = ""

.demo    → backgroundColor = rgba(0,0,0,0)   boxShadow = none   backdropFilter = none
.eyebrow → backgroundColor = rgba(0,0,0,0)   boxShadow = none   backdropFilter = none
body     → backgroundImage = none
```

즉 현재 화면에서:

| 의도 | 실제 |
|---|---|
| `box-shadow` 34곳 | 전부 `none` |
| `backdrop-filter`(유리) 9곳 | 전부 `none` |
| 유리 패널 바탕 `var(--glass)` | 전부 **투명** |
| 배경 광원(`body` 방사형 3겹) | `none` |

`home.png` 를 보면 이 결과가 그대로 나온다. 히어로 오른쪽 "지금 어디까지 왔나요" 패널은
**바탕이 없어서** 게임 아트가 그대로 비치고, 티어 버튼 글자가 배경 산·연기와 겹쳐 읽히지 않는다.
패널이 떠 있는 게 아니라 유령처럼 걸쳐 있다. 이것이 "구식으로 보인다"는 인상의 1차 원인이다.
디자인 판단의 문제가 아니라 **작동하지 않는 코드**의 문제다.

> 이 결함은 `docs/DESIGN-BRIEF.md` 가 명시한 "`box-shadow` 사용처 0건" 검수 항목을
> 형식적으로는 통과시킨다 — 실제로 그림자가 0개이기 때문이다. 검수표가 의도가 아니라
> 결과만 세고 있었다.

### 01-3. 토큰 수준의 낡음

| 항목 | 현재 | 문제 |
|---|---|---|
| 모서리 | `1 / 2 / 3 / 4 / 8 / 14 / 999px` + `calc(--radius*2)` + `calc(--radius*3)` = **9종** | 기준 반경은 3px 인데 실제로는 9가지가 섞였다. 사다리가 없어서 크기 위계가 반경으로 읽히지 않는다 |
| 상호작용 피드백 | CSS 전체에 `transition` 선언 **6개** | 카드·행·토글·필터 대부분이 눌러도 아무 반응이 없다. 2026년 제품 UI 에서 가장 즉각적으로 "낡았다"고 느껴지는 지점 |
| 경계 대비 | `--line-strong: #38455a` = 배경 대비 **2.02:1** | WCAG 1.4.11(비텍스트 3:1) **미달**. 브리프가 3.7:1 로 검증했다고 적은 값(`#69717C`)은 구현되지 않았다 |
| 본문 크기 | 표·사이드바·도구줄까지 전부 15~17px | Linear 은 제품 UI 를 13~14px 로 짠다(실측). 데이터 도구에서 17px 본문은 밀도를 절반으로 깎는다 |
| 제목 굵기 | `h1` 800, `h2`~`h4` 700/600 | 2026년 관용구는 가변축 중간값(Linear h1 = **510**, Geist/shadcn = **600**). 800은 뭉툭하다 |
| 강조색 | 주황 11.1:1 + 청록 10.0:1 **두 개 다 최대 채도** | 둘 다 고대비라 화면이 "검정 위 네온"이 된다. 위계가 아니라 경쟁이다 |
| 색공간 | hex 만. `oklch()` 0건 | 명도 사다리를 손으로 찍어서 단계 간격이 고르지 않다 |
| 최신 CSS | 컨테이너 쿼리 0 · `:has()` 0 · 네이티브 중첩 0 · `@layer` 0 · subgrid 0 · View Transitions 0 · `popover` 0 · `light-dark()` 0 | 유일하게 쓰는 최신 기능이 `color-mix()`(39곳)와 장식용 스크롤 연동 애니메이션이다 |

## 02. 참고할 실물

전부 직접 열어 캡처하고 **계산된 스타일과 토큰 값을 추출**했다. 아래 수치는 인용이 아니라 실측이다.

### Linear — `https://linear.app` (`ref-linear.png`)

가장 참고할 만한 대상이다. 우리와 같은 다크 기본 · 정보 밀도 도구다.

```
body   bg rgb(8,9,10)   fg rgb(247,248,248)   font "Inter Variable" + Berkeley Mono(코드)
h1     64px / lh 64px(1.0) / ls -1.408px(-0.022em) / weight 510
본문 p  15px / lh 24px(1.6) / ls -0.165px(-0.011em) / weight 400
빈출 크기  16px×1154  14px×273  13.3px×198  13px×194  12px×158
반경     2px×42  6px×40  4px×27  8px×12  12px×12  9999px×18
그림자   rgba(0,0,0,.03) 0 1.2px 0 0        ×31   ← 머리카락 굵기의 "턱"
        rgb(35,37,42) 0 0 0 1px inset      ×5    ← 테두리 대신 안쪽 1px 링
```

배울 것 세 가지.

1. **배경은 거의 순수 무채색 근검정이다**(8,9,10). 우리 `#0a0d12` 는 청색 편향이 눈에 띈다.
   본문색도 우리(`#e8ecf1`)보다 밝다(247,248,248).
2. **깊이를 그림자로 만들지 않는다.** `inset 0 0 0 1px`(안쪽 링) + 불투명도 0.03짜리
   1.2px 턱이 전부다. 큰 소프트 섀도가 없다. 우리가 되살릴 `--lit` 이 향해야 할 방향이다.
3. **제목이 굵지 않다.** 64px 을 weight 510 으로 쓴다. 크기로 위계를 만들고 굵기는 아낀다.
   그리고 배경이 게임 아트가 아니라 **제품 화면 실물**이다 — 실제 데이터가 들어찬 UI 자체가
   히어로 이미지다. 우리 랜딩의 라이브 위젯 전략과 같은 발상인데, Linear 쪽은 그 위젯이
   화면의 60%를 쓰고 배경 이미지는 없다.

### Vercel Geist — `https://vercel.com/geist/colors` (`ref-geist-colors.png`)

토큰 873개를 그대로 읽었다. 우리 토큰 파일이 참고할 어휘가 여기 다 있다.

```

--geist-radius: 6px          --geist-marketing-radius: 8px
--geist-form-height: 36px    --geist-form-font: .875rem(14px)     ← 폼 높이를 토큰으로 고정
--ds-shadow-border-base:   0 0 0 1px #00000014
--ds-shadow-border-inset:  inset 0 0 0 1px #00000014
--ds-shadow-xs:     0px 1px 2px #0000000a
--ds-shadow-medium: 0px 2px 2px #0000000a, 0px 8px 8px -8px #0000000a
--ds-shadow-modal:  <border> , 0 1px 1px #05, 0 8px 16px -4px #0a, 0 24px 32px -8px #0f
```

배울 것: **그림자를 "고도(elevation) 이름"으로 관리하고, 모든 고도에 1px 링을 포함시킨다.**
`shadow-border-*` 라는 이름 자체가 "그림자와 테두리는 한 세트"라는 선언이다.
그리고 색은 10단 스케일에 **자리별 의미**를 못박았다 — 1~3 배경(기본/호버/활성),
4~6 테두리(기본/호버/활성), 7~8 고대비 배경, 9~10 글자/아이콘. 우리 팔레트에는 이 자리 개념이 없다.

### shadcn/ui — `https://ui.shadcn.com` (`ref-shadcn.png`)

2026년에도 가장 큰 참조 대상이다(★121,721 / 마지막 푸시 2026-08-20). 성격이 바뀌었다 —
"컴포넌트 모음"이 아니라 **레지스트리 배포 플랫폼**이고, 프리미티브 계층을 Radix / Base UI /

--radius: .625rem(10px)

### Supabase — `https://supabase.com/dashboard/sign-in` (`ref-supabase.png`)

다크 데이터 도구의 폼 관용구를 확인용으로 봤다. 평평한 근검정 배경, 그라디언트 0,

우리 "화면당 주황 채움 1개" 규칙이 실제 제품에서 어떻게 보이는지의 표본이다.

## 03. 바꿀 것 (우선순위 순)

### P0 — 고도 사다리를 완성한다 (토큰 정의는 조사 중 완료됨)

**(a) 지금** 조사 시작 시점에는 `--glass` `--glass-blur` `--glass-sat` `--lit` `--lit-strong`
`--ambient-cool` `--ambient-warm` 이 40여 곳에서 참조되지만 정의가 없었고, `box-shadow` 34곳 ·
`backdrop-filter` 9곳 · 패널 바탕 전부 · 배경 광원 전부가 브라우저에서 버려지고 있었다.
**조사 도중 다른 작업이 이 7개를 정의했다**(01-1 상단 주). 남은 문제는 링 색이 어두운 면 위에서
보이지 않는 것(`--lit` 이 `--line`, 대비 1.4:1)과 고도가 2단뿐이라는 것이다.

**(b) 바꾼다** 아래 05절 값으로 `tokens.css` 에 정의한다. 단 **원래 의도(유리 + 발광)
그대로가 아니라 Linear/Geist 방식으로** — 큰 소프트 섀도가 아니라 `inset 0 0 0 1px` 링 +
아주 얕은 턱. `backdrop-filter` 는 지도·설계 화면의 **떠 있는 도구줄에만** 남기고
정적 패널에서는 걷어낸다(불투명 바탕으로 대체).

**(c) 왜** 이것이 "구식으로 보인다"의 1차 원인이다. 다른 어떤 변경보다 인상 차이가 크고
디프가 작다. 그리고 지금 상태는 접근성 문제이기도 하다 — 히어로 패널 글자가 배경 그림 위에
바탕 없이 얹혀 있다.

**(d) AI 티로 안 돌아가는 이유** 되살리는 값이 2023년 글래스모피즘(`blur(20px)` + 반투명 흰
테두리 + 큰 그림자)이 아니라 2026년 실측값(불투명도 0.03~0.08 링, 1~2px 턱)이기 때문이다.
Linear 의 그림자 31곳 중 최다 사용값이 `rgba(0,0,0,.03) 0 1.2px 0 0` 이라는 것이 근거다.

### P1 — `fx.css` 의 2023년 지문을 걷어낸다

**(a) 지금** Border Beam(테두리를 도는 빛), Retro Grid(원근 격자 바닥), Shimmer(버튼 위 광택),
Gradient Text(흐르는 그라디언트 글자), 그리고 `.hero h1 .glow` 그라디언트 제목,
`.eyebrow` 알약 뱃지 + 초록 점, 히어로 아트 스크롤 확대.

**(b) 바꾼다** 이 목록을 **전부 삭제한다.** 대체물은 넣지 않는다 — 자리를 비우는 게 아니라
P3(밀도)과 P4(피드백)가 그 자리를 정보로 채운다. 히어로 배경 게임 아트는 **유지하되**
위젯 뒤쪽만 불투명 패널로 덮어 글자 대비를 확보하고, 스크롤 확대 애니메이션만 제거한다.

**(c) 왜** Magic UI/Aceternity 계열 효과는 2023~2024년 AI 랜딩의 표준 장식이었다.
2026년 상위 제품 7곳(Linear·Vercel·Stripe·Supabase·Clerk·Raycast·Cursor) 어디에도
회전하는 테두리 빛도, 원근 격자 바닥도, 그라디언트 채움 제목도 없다. 이것들은 유행을
따른 결과가 아니라 **유행이 지나간 뒤 남은 것**이다. 사용자가 "2년 전 앱 같다"고 말한
바로 그 2년이 이 효과들의 전성기다.

**(d) AI 티로 안 돌아가는 이유** 여기서 걷어내는 것들이 바로 AI 지문 목록의 항목이다 —
그라디언트 제목(#2), 뱃지-헤드라인(감별 지문), 의미 없는 장식 모션(#9). 걷어내는 것이
지문 회피 방향이다. **다만 이것만 하면 다시 회색 상자가 된다** — 그래서 P0 와 반드시 같이 간다.

### P2 — 모서리·고도·경계를 사다리로 재정의한다

**(a) 지금** 반경 9종(`1/2/3/4/8/14/999px` + calc 파생 2종). 그림자는 죽어 있고,
`--line-strong` 은 대비 2.02:1 로 WCAG 1.4.11 미달.

**(b) 바꾼다** 05절의 5단 반경 사다리(`4/6/8/12/full`)와 4단 고도 사다리,
그리고 3단 경계(`장식 / 구조 / 상호작용`)로 정리한다. 상호작용 경계는 3.27:1 로 올린다.

**(c) 왜** Raycast 는 7단, Linear 은 7단, Cursor 는 7단, Geist 는 이름 붙인 고도 프리셋으로
관리한다. 공통점은 **값이 몇 개인지가 아니라 이름이 붙어 있고 자리가 정해져 있다는 것**이다.
지금은 3px 기준값이 있는데 실제로는 9가지가 섞여 있어 크기 위계가 반경으로 읽히지 않는다.

**(d) AI 티로 안 돌아가는 이유** AI 지문 #5는 "**과도한** 둥근 모서리 + **균일한** 은은한
그림자"다. 우리가 하려는 것은 정반대다 — 최대 12px(마케팅 컨테이너만 16px)로 **작게** 잡고,
그림자를 균일하게 뿌리는 게 아니라 z 계층별로 **다르게** 준다. `ai-tells.md` 가 제시한
대체안("반경을 2~3단계로 의도적으로 정하고, 그림자 대신 발광 테두리나 명도차")과 같은 방향이다.

### P3 — 앱 화면의 밀도를 올린다

**(a) 지금** 모든 앱 페이지가 `눈썹 + 40px H1 + 리드문` 블록으로 시작해 `h1` 이 y=217px 에서
시작한다. 표·사이드바·도구줄 글자가 15~17px. `/codex/tiers/3/` 는 전체 요소 247개로 1935px 를 쓴다.

**(b) 바꾼다**
- 앱 화면(도감·지도·설계) 제목을 **머리띠에 붙는 24px 한 줄**로 내리고 눈썹·리드문은 없앤다.
  긴 설명이 필요하면 첫 섹션으로 옮긴다. 회수되는 세로 공간 약 **180px**.
- 05절의 **UI 스케일(11/12/13/14px)** 을 새로 만들어 표 셀·사이드바 행·도구줄·칩에 쓴다.
  본문 산문(가이드 문단)은 한국어 조판 규칙에 따라 **17px/1.7 을 유지**한다. 이 둘은 다른 스케일이다.
- 티어 0~9 선택을 80px 카드 10장에서 **36px 세그먼트 한 줄**로 바꾼다.
- 싱크 상점 3열 카드 그리드를 **컨테이너 쿼리 기반 자동 채움 그리드**로 바꿔
  1440px 에서 한 줄에 6~8개가 들어가게 하고, 카드 내부 행 정렬은 **subgrid** 로 맞춘다.
- 랜딩과 가이드 산문은 지금 밀도를 유지한다. 읽는 화면과 쓰는 화면을 다르게 짠다.

**(c) 왜** Linear 제품 UI 의 최빈 글자 크기는 13~14px 이고, shadcn 문서는 787개 요소 중
713개가 14px 다. 데이터 도구에서 17px 균일 본문은 밀도를 절반으로 깎는다. 우리 화면은
정보 밀도가 곧 가치인 도구인데(자원 노드 338개, 상점 173품목, MAM 120건) 그것을 못 보여준다.
`codex-shop.png` 에서 1440px 폭에 6개 품목만 보이는 것이 그 결과다.

**(d) AI 티로 안 돌아가는 이유** AI 지문 #3(아이콘 3열 균등 카드)에서 **멀어지는** 방향이다.
3열 균등 카드가 지문인 이유는 "정보가 적은데 공간을 크게 쓰기" 때문이다. 밀도를 올리면
그 형태 자체가 성립하지 않는다. 그리고 카드에 들어가는 것이 Lucide 선 아이콘이 아니라
**게임 실물 아이템 이미지**라는 점은 `ai-tells.md` #4 의 권장 대체안("제품 실물을 쓴다")과 일치한다.

### P4 — 상호작용 피드백을 붙인다

**(a) 지금** CSS 전체에 `transition` 6개. 카드·표 행·필터 체크박스·티어 버튼·도구줄
대부분이 눌러도 반응이 없다. 활성(`:active`) 상태는 어디에도 없다.

**(b) 바꾼다** 05절 모션 사다리(70/130/200/320ms)를 두고, **누를 수 있는 모든 요소에**
호버(경계+바탕), 활성(1px 눌림 또는 바탕 한 단 어둡게), 포커스(2px 링) 3상태를 준다.
표 행 호버는 이미 있으니 유지. 지도 필터·티어 세그먼트·상점 카드에 새로 붙인다.

**(c) 왜** 2026년 제품 UI 에서 가장 즉각적으로 "낡았다"고 느껴지는 지점이 무반응이다.
색이 아니라 **반응 속도**가 최신감을 만든다. 70ms 호버는 "즉시"로 느껴지고 300ms 는 굼뜨게 느껴진다.

**(d) AI 티로 안 돌아가는 이유** AI 지문 #9는 "**의미 없는 페이드인만 반복**"이고,
대체안은 "모션이 정보를 나르게 하라"다. 상태 피드백은 정의상 정보 모션이다 —
"이건 누를 수 있다", "지금 눌렀다", "지금 여기 포커스가 있다". 진입 애니메이션이 아니다.
`transform: scale()` 확대 호버는 계속 금지한다.

### P5 — 색을 oklch 로 다시 깔고 강조를 정리한다

**(a) 지금** hex 만 사용. 주황 11.1:1 · 청록 10.0:1 로 둘 다 최대 대비. 배경 `#0a0d12` 는
청색 편향. 명도 사다리가 손으로 찍혀 있어 `--surface`(#111722)와 `--raised`(#18202c)의
간격이 고르지 않다.

**(b) 바꾼다** 05절 팔레트로 교체. 배경을 거의 무채색 근검정으로 내리고,
`--ink` 를 밝히고, 명도 사다리를 oklch L 값으로 등간격 배치한다.
**주황은 유일한 브랜드 강조로 남기고, 청록은 채도를 낮춰 "상호작용" 역할로만 강등한다.**

**(c) 왜** Linear(8,9,10) · Raycast(7,8,10) · Geist(0,0,0) 전부 무채색 근검정이다.
청색 편향 배경은 화면 전체에 옅은 색조를 씌워 자원 색 칩(파랑/청록 계열이 여럿)과 간섭한다.
oklch 는 명도 축이 지각적으로 균일해서 `L 0.16 / 0.21 / 0.25 / 0.29` 같은 등간격 사다리가
실제로 등간격으로 보인다 — hex 로는 이게 안 된다. Tailwind v4 가 팔레트를 통째로 oklch 로
옮긴 이유도 같다.

**(d) AI 티로 안 돌아가는 이유** 슬롭 팔레트는 `indigo-500 #6366F1` / `violet-500 #8B5CF6` /
`purple-500 #A855F7` 다. 우리는 보라 계열을 쓰지 않고, 색을 게임 세계(FICSIT 주황)에서
유도한다는 원칙을 그대로 유지한다. 바뀌는 것은 **색상(hue)이 아니라 명도 사다리의 정밀도**다.

Newly available 이므로 점진적 향상으로 쓴다. 나머지는 쓰지 않는다.

## 04. 바꾸면 안 되는 것

사용자 요구는 "최신 트렌드 반영"이다. 그런데 **2026년 트렌드 목록과 AI 지문 목록은 상당 부분
같은 항목을 담고 있다.** 유행을 따라가면 지문으로 되돌아간다. 경계는 다음과 같다.

| 유지 | 이유 |
|---|---|
| **3역할 서체 분리**(Wanted Sans / Pretendard / JetBrains Mono) | 이것이 지금 가장 잘 되어 있는 부분이다. 2026년 상위 제품 7곳 전부 서체를 하나로 통일하지 않는다(Linear = Inter + Berkeley Mono, Cursor = CursorGothic + Berkeley Mono + 세리프, Raycast = Inter + JetBrains Mono + Instrument Serif). AI 지문 #1이 정확히 "단일 폰트 통일"이다 |
| **수치 고정폭 + `tabular-nums`** | 표에서 자릿수 정렬은 타협 대상이 아니다 |
| **모노 번호 섹션 마커, 이모지 0개** | 지문 #7 |
| **좌측 정렬 · `word-break: keep-all` · 본문 자간 0 · 행간 1.7** | 한국어 조판 요건. 3절 참조 |
| **자원 색에 텍스트 라벨 병기** | 색각 이상 대응. 색만으로 인코딩하지 않는다 |
| **소셜 프루프 0 · 로고월 0 · 사용자수 0** | 지문 #10 |
| **게임 실물 아이템 이미지 사용** | 지문 #4의 권장 대체안이 "선 아이콘 대신 제품 실물". Lucide/Heroicons 로 바꾸면 그게 후퇴다 |
| **`:focus-visible` 링 유지** | 지문 #13 |
| **다크 단일 테마** | 게임과 알트탭하며 쓰는 도구다. `light-dark()` 를 쓸 수 있게 됐다는 이유로 라이트 테마를 반쯤 만들지 마라 — `tokens.css` 주석이 이미 그 결론을 적어 뒀다 |
| **보라/인디고 배제** | 슬롭 팔레트의 핵심 |

### 명시적으로 도입하지 않을 "2026 트렌드"

| 안 쓴다 | 이유 |
|---|---|
| 그라디언트 채움 제목 | 슬롭 목록. P1에서 걷어내는 대상이다 |
| 글래스모피즘(강한 블러 + 반투명 흰 테두리) | 감별 지문 목록에 명시. 떠 있는 도구줄에만 약하게 남긴다 |
| 회전 테두리 빛(Border Beam) / 원근 격자(Retro Grid) | 2023년 지문 |
| 숫자 카운트업 · 타이핑 효과 · 무한 마퀴 | 정보를 나르지 않는다 |
| 진입 시 stagger 페이드인 | 지문 #9 |
| React 컴포넌트 라이브러리(shadcn/Base UI/Radix) | ADR-0009. 값만 참고하고 코드는 도입하지 않는다 |
| CSS-only 캐러셀(`::scroll-marker`) | Chromium 전용 |
| 커스텀 `<select>`(`appearance: base-select`) | Chromium 전용 |

| 스크롤 연동 장식 애니메이션 | 지금 쓰는 유일한 용도가 장식이다. 걷어낸다 |

### 5-5. 모서리 — 5단 사다리

```css
--r-1:    4px;    /* 칩, 뱃지, 체크박스, 작은 아이콘 상자 */
--r-2:    6px;    /* 버튼, 입력, 세그먼트, 표 셀 강조 */
--r-3:    8px;    /* 패널, 카드, 사이드바 블록 */
--r-4:   12px;    /* 큰 컨테이너, 다이얼로그, 팝오버 */
--r-full: 9999px; /* 상태 점·개수 알약 전용 */
```

**이 5개 밖의 값 금지.** 현재 쓰이는 `1px`·`2px`·`3px`·`14px`·`calc(--radius*2)`·
`calc(--radius*3)` 는 전부 위 중 하나로 접는다. 근거: Raycast 7단, Linear 7단, Cursor 7단이
전부 4px 을 최소 단위로 시작한다. 우리는 화면 종류가 적으니 5단이면 충분하다.

### 5-6. 고도 — 그림자가 아니라 "링 + 턱"

```css
--ring:   inset 0 0 0 1px #ffffff0d;                              /* 모든 면의 기본 */
--elev-1: inset 0 0 0 1px #ffffff0a, 0 1px 2px #00000059;         /* 패널·카드 */
--elev-2: inset 0 0 0 1px #ffffff0f, 0 4px 12px -2px #00000073;   /* 떠 있는 도구줄·드롭다운 */
--elev-3: inset 0 0 0 1px #ffffff14, 0 0 0 1px #00000080,
          0 16px 40px -12px #000000a6;                             /* dialog · popover */
```

규칙 세 가지.
1. **모든 고도에 안쪽 1px 링이 포함된다.** Geist 의 `shadow-border-*` 와 같은 발상 —
   그림자와 테두리는 한 세트다. 어두운 배경에서 면의 위쪽 모서리를 살리는 것은 그림자가 아니라 링이다.
2. **한 요소에 고도를 두 개 겹치지 않는다**(Geist Materials 의 명시 규칙).
3. `--elev-3` 만 큰 소프트 섀도를 갖는다. 나머지는 2~12px 범위다.

`backdrop-filter` 는 `--elev-2` 를 쓰는 **떠 있는 요소에만** 허용하고 값은
`blur(12px) saturate(1.4)` 로 고정한다. 정적 패널은 불투명 `--bg-1` 을 쓴다.

### 5-7. 타이포 — 두 개의 스케일

**이 저장소의 가장 큰 조판 오류는 산문과 UI 를 같은 스케일로 짠 것이다.** 분리한다.

**A. 산문 스케일** — 가이드 본문, 랜딩 설명문. 한국어 조판 규칙 적용.

| 토큰 | 크기 | 행간 | 자간 | 굵기 |
|---|---|---|---|---|
| `--p-lg` | 19px | 1.7 | 0 | 400 |
| `--p-md` | **17px** | **1.7** | **0** | 400 |
| `--p-sm` | 15px | 1.65 | 0 | 400 |
| `--p-xs` | 13px | 1.6 | 0 | 400 |

KRDS 기준을 그대로 유지한다. **여기는 건드리지 않는다.**

**B. UI 스케일** — 표 셀, 사이드바 행, 도구줄, 칩, 라벨, 버튼. 새로 만든다.

| 토큰 | 크기 | 행간 | 자간 | 굵기 |
|---|---|---|---|---|
| `--ui-lg` | 14px | 1.5 | 0 | 400/500 |
| `--ui-md` | **13px** | **1.5** | 0 | 400/500 |
| `--ui-sm` | 12px | 1.45 | 0 | 500 |
| `--ui-xs` | 11px | 1.4 | +0.06em | 500, 모노, 대문자 |

근거: Linear 제품 UI 최빈값 13~14px, shadcn 문서 14px(787개 중 713개), Geist 폼 14px.
한국어 13px 은 산문에는 작지만 **표 셀·라벨에는 충분하다** — 표는 훑어보는 텍스트지 읽는 텍스트가 아니다.
현재 `table { font-size: 15px }` 를 `--ui-md`(13px)로 내리면 같은 화면에 행이 약 1.2배 더 들어간다.

**C. 제목 — 굵기를 낮춘다**

| 토큰 | 크기 | 행간 | 자간 | 굵기 |
|---|---|---|---|---|
| `--t-display` | `clamp(34px, 4.6vw, 56px)` | 1.10 | -0.030em | **650** |
| `--t-h1` | `clamp(26px, 3vw, 36px)` | 1.20 | -0.022em | **640** |
| `--t-h2` | `clamp(21px, 2.2vw, 27px)` | 1.30 | -0.015em | **620** |
| `--t-h3` | 19px | 1.40 | -0.010em | 600 |
| `--t-h4` | 16px | 1.45 | -0.005em | 600 |

현재 `h1` 800 / `h2`~`h4` 700 에서 내린다. Linear h1 = **weight 510**, shadcn/Geist h1 = **600**.
Wanted Sans 와 Pretendard 는 둘 다 가변축이므로 620~650 이라는 중간값을 **비용 없이** 쓸 수 있다.
한글 700+ 를 큰 크기로 쓰면 획이 뭉쳐 뭉툭해진다 — 낮추는 편이 한글에서 특히 유리하다.

행간 주의: Linear 은 h1 을 **1.0**으로 짠다. 한글에는 그대로 못 쓴다(받침이 잘린 것처럼 보인다).
**1.10 이 한글 디스플레이의 하한**이다.

### 5-8. 간격

현재 `--s1`~`--s32`(4/8/12/16/20/24/32/40/48/64/80/96/128)를 **그대로 유지한다.**
Geist 의 `--geist-space-*` 와 사실상 동일하고, 4px 배수 원칙도 맞다.

추가할 것 하나: `--s0: 2px` — 밀도 높은 컨트롤(칩 안쪽 여백, 세그먼트 사이 간격)에 필요하다.
현재는 4px 이 최소라 표 셀 여백을 더 줄일 수 없다.

컨테이너: `--page: 1180px` 유지. 단 지도·설계처럼 **캔버스가 주인공인 화면은 `--page` 를 벗어나
전체 폭을 쓴다**(`--page-wide: 1600px`). 현재 지도가 1180px 에 갇혀 있는 것이 밀도 손실 원인 중 하나다.

### 5-9. 모션 — 4단 사다리

```css
--dur-1:  70ms;   /* 색·경계 호버. "즉시"로 느껴지는 상한 */
--dur-2: 130ms;   /* 체크박스, 토글, 세그먼트 이동 */
--dur-3: 200ms;   /* 아코디언, 패널 열림 (grid-template-rows) */
--dur-4: 320ms;   /* View Transition — 내용 교체에만 */

--ease-out:    cubic-bezier(0.16, 1, 0.30, 1);   /* 기본. 빠르게 나가 부드럽게 안착 */
--ease-in-out: cubic-bezier(0.65, 0, 0.35, 1);   /* 위치 이동 */
```

현재 `--dur-fast: 90ms` / `--dur: 160ms` 두 개뿐이고 실제 사용은 6곳이다.
`--ease: cubic-bezier(0.32,0.72,0,1)` 는 나쁘지 않으나 위 값이 더 표준적이다.

**적용 의무**: 누를 수 있는 모든 요소에 `:hover`(경계 → `--edge-3`, 바탕 → `--bg-3`),
`:active`(바탕 → `--bg-4`), `:focus-visible`(2px `--interactive` 링 + 2px offset) 3상태.

`prefers-reduced-motion: reduce` 에서 `--dur-1`~`--dur-4` 를 전부 `0.01ms` 로,
View Transition 비활성화, **상태 변화 자체는 즉시 반영**.

## 07. 한국어 조판 — 최신 관행이 한글에서도 성립하는가

2026년 참고 제품들의 조판 값을 한글에 그대로 옮기면 **일부는 깨진다.** 항목별 판정.

| 2026 관행 (실측) | 한글 적용 | 판정 |
|---|---|---|
| 본문 15px / 행간 1.6 (Linear) | ✗ | 한글은 정사각 블록에 가까워 같은 크기에서 라틴보다 답답하다. **산문은 17px / 1.7 유지**(KRDS·W3C 한국어 레이아웃 요구사항). 이건 유행보다 우선한다 |
| 본문 자간 -0.011em (Linear) | ✗ | 한글 본문 자간은 **0**이 정본(KRDS). 음수 자간은 한글에서 글자 사이 공간이 아니라 **글자 자체가 붙어 보인다**. 적용하지 않는다 |
| UI/표 13~14px | ○ | 표 셀·사이드바·라벨은 읽는 텍스트가 아니라 **훑는 텍스트**다. 한글 13px 도 충분히 판독된다. 05절 UI 스케일이 이것 |
| 제목 자간 -0.02 ~ -0.05em | ○ | 큰 크기 굵은 글자는 한글도 조여야 한다. 현재 `-0.02` ~ `-0.03` 이 이미 맞다. 단 **-0.035em 을 넘기지 않는다** — 라틴은 -0.05em 도 견디지만 한글은 받침이 앞 글자에 닿는다 |
| 제목 굵기 600 전후 | ◎ | **한글에서 오히려 더 유리하다.** 800 짜리 한글 대제목은 획 사이 공간이 막혀 뭉툭해진다. 620~650 이 획 구조를 살린다 |
| 제목 행간 1.0 (Linear h1 = 64/64) | ✗ | 한글 받침이 잘린 것처럼 보인다. **1.10 이 하한** |
| `text-wrap: balance` | ○ | `word-break: keep-all` 과 함께 쓰면 어절 단위로 줄을 고르게 나눈다. 한글에 특히 잘 맞는다. 유지 |
| `text-wrap: pretty` | ✗ | Firefox 미구현 + 한글에서 주 목적(외톨이 단어 방지)은 `keep-all` + `balance` 로 이미 거의 해결 |
| 밀도 높은 다단 레이아웃 | ○ | 단, **본문 한 줄 상한 `--measure: 52em` 유지**. 한글은 글자 폭이 커서 같은 em 에 글자 수가 적다. 현재값이 이미 조정된 값이다 |
| 한글·숫자 사이 공백 없음 | ○ | 유지. `철판 20개/분` |

**결론: 산문 조판(크기·행간·자간)은 한국어 규칙이 유행을 이긴다. 밀도·굵기·모서리·고도·모션은
유행 쪽이 맞다.** 05절이 스케일을 둘로 나눈 이유가 이것이다.

한 가지 위험: 서체 서브셋. `npm run font` 로 쓰는 글자만 잘라내는 구조인데,
제목 굵기를 620~650 같은 중간값으로 바꾸면 **가변축이 서브셋에 살아 있어야 한다.**
`--font-display` 는 `font-weight: 100 900` 로 선언돼 있으니 문제없지만,
서브셋 스크립트가 축을 고정(`instancing`)하고 있지 않은지 확인이 필요하다.

## 08. 당장 바꿀 것 5개

인상 차이가 큰 순서다. 1번과 2번은 **반드시 같이** 나간다 — 하나만 하면 각각 다른 방향으로 실패한다.

### 1. 고도 사다리를 완성한다 — `tokens.css` ~~죽어 있는 토큰 7개를 정의한다~~

**토큰 정의 자체는 조사 중 다른 작업이 이미 마쳤다**(01-1 상단 주 참조). 남은 것은 두 가지다.

- `--lit` 의 링 색을 `var(--line)`(#1f2733, 대비 1.4:1) 대신 **흰색 알파**(`#ffffff0a`~`#ffffff0f`)로
  바꾼다. 면 색이 무엇이든 위쪽 모서리가 살아나기 때문이다 — Linear 이 `rgb(35,37,42) 0 0 0 1px inset`
  대신 어두운 면에 밝은 링을 쓰는 이유이자, Geist `--ds-shadow-border-inset` 의 구성이다.
- 05-6절의 **4단 고도 사다리**(`--ring` / `--elev-1..3`)로 확장한다. 지금은 `--lit` / `--lit-strong`
  2단이고 얕은 턱(`0 1px 2px`)이 없어 패널·떠 있는 도구줄·다이얼로그가 같은 높이로 읽힌다.

여전히 가장 작은 디프로 가장 큰 인상 변화를 내는 자리다.

### 2. `fx.css` 를 삭제하고 그라디언트 제목·알약 뱃지·히어로 패럴랙스를 걷어낸다

Border Beam · Retro Grid · Shimmer · Gradient Text · `.hero h1 .glow` · `.eyebrow` 점 뱃지 ·
`animation-timeline: scroll()` 히어로 확대. 이것들이 "2년 전 앱"이라는 인상의 실제 출처다.
1번 없이 이것만 하면 회색 상자로 되돌아간다.

### 3. 앱 화면 밀도를 올린다 — UI 스케일 도입 + 페이지 머리 축소

`--ui-md`(13px) 스케일을 만들어 표 셀·사이드바 행·도구줄·칩에 적용하고,
도감·지도·설계의 `눈썹 + 40px H1 + 리드문` 블록을 **24px 한 줄 제목**으로 접는다.
화면당 세로 180px 회수 + 표 행 약 1.2배 증가. 데이터 도구처럼 보이기 시작하는 지점이다.

### 4. 상호작용 3상태를 전면 적용한다

`transition` 6개 → 누를 수 있는 모든 요소에 hover/active/focus-visible.
`--dur-1: 70ms` + `--ease-out: cubic-bezier(0.16,1,0.30,1)`.
색을 하나도 안 바꿔도 "반응하는 앱"으로 느껴진다. 지금은 티어 카드도 지도 필터도
상점 카드도 눌러서 아무 일도 일어나지 않는 것처럼 보인다.

### 5. 모서리 사다리 5단 + 경계 대비 수정

반경 9종 → `4 / 6 / 8 / 12 / full`. `--line-strong` 2.02:1 → `--edge-3` 3.27:1.
후자는 WCAG 1.4.11 위반 수정이라 선택 사항이 아니다.
반경 정리는 화면 전체의 "손으로 찍은 느낌"을 없애는, 조용하지만 확실한 변화다.
