# 공장 배치 패턴 (Factory Layout Patterns)

> 기준 버전: **Update 1.2** (스테이블 2026-06-02, UE 5.6.1, 콘솔 동시 출시)
> 1차 출처: 공식 위키 satisfactory.wiki.gg / 교차검증: Steam 토론, 커뮤니티 가이드, 나무위키

## 요약

- 배치 패턴은 **메인 버스 / 셀(모듈) / 수직 타워** 3종이며, Satisfactory에서는 Factorio식 메인 버스의 이점이 약하다. 수직 축이 열려 있고 중간재가 보통 2~4개 레시피에서만 재사용되기 때문이다. 커뮤니티 주류는 **자원 노드 근처 셀 생산 + 완제품만 중앙 집결**이다.
- 매니폴드 vs 로드 밸런서 논쟁의 결론은 "매니폴드 기본, 밸런서는 예외": **포화 후 처리량은 동일**하고 매니폴드가 자재·공간·확장성에서 앞선다. 밸런서는 즉시 100%가 필요한 곳(기차역, 저장소, 싱크)에만 쓴다. 단, 총 처리량이 벨트 1개 용량을 넘으면 매니폴드는 성립하지 않는다(인젝티드 매니폴드 필요).
- 모든 격자의 기준은 **파운데이션 8m × 8m**이고 월드 그리드는 수평 800cm / 수직 100cm로 스냅한다. 블루프린트 디자이너 내부 치수는 Mk1 32m(4×4) / Mk2 40m(5×5) / Mk3 48m(6×6)으로 **전부 8의 배수** — 즉 디자이너는 파운데이션 격자에 정확히 정렬된다.
- 층 분리는 배관(수직 양정 제약) → 생산 → 버스 순으로 물리 제약이 강한 쪽을 먼저 고정하는 것이 실무 관행이다. 펌프 Mk1 양정 22m, 컨베이어 리프트 최대 48m가 층고 설계의 상한을 결정한다.
- 철거 시 자재 **100% 환급**이므로 배치 실험 비용은 시간뿐이다. 이것이 "일단 짓고 뜯어라"가 성립하는 근거다.

- 저장 조건: 건물이 **경계 프레임 안에 완전히** 들어와야 한다. 단 **기둥(Pillar)은 가장자리에 부분적으로 걸쳐도 된다**. → 가장자리 정렬 트릭의 근거.
- 블루프린트 스냅 3종: ①기본 = 놓인 파운데이션에 **수평 1m / 수직 0.5m** 스냅, ②블루프린트 모드 = **블루프린트끼리 중심점 기준** 스냅, ③오토커넥트(R) = 컨베이어·파이프·철도·차량경로가 **16m 이내** 입출력에 자동 연결 (Update 1.1 추가).
- 블루프린트 파일 포맷은 크기를 **8m 단위**로 X/Y/Z 각각 기록한다.
- **하위 등급 디자이너에서 만든 블루프린트를 상위 등급 디자이너 안에 넣을 수 있다. 역방향은 불가.** → 4층 적층·모듈 중첩 기법의 근거.
- 지열 발전기(Geothermal Generator)는 디자이너 안에 지을 수 없다.
- 디자이너에서 철거한 자재는 **먼저 보관함(storage box)으로, 넘치면 개인 인벤토리**로 반환된다.
- 일반 철거(Dismantle, F)는 **건설 비용 100% 환급**이며 내용물도 함께 반환. 인벤토리가 가득 차면 크레이트가 스폰된다.

## 설계에 주는 시사점

### 1. 세 가지 배치 패턴의 선택 기준

| 패턴 | 언제 쓰나 | 강점 | 약점 |
|---|---|---|---|
| **메인 버스(Main Bus)** | 여러 라인이 **동일한** 잉곳·로드·와이어를 공유할 때 | 중앙 집중, 분기 추가로 확장 | Satisfactory에서는 이점 약함. 밸런스 관리 필요, 하류 기아 발생 |
| **셀/모듈(Cell, City Block)** | 대부분의 경우 — 특히 원격 노드 기반, 전력 소모 큰 라인 | 재건축 고통 최소, 블루프린트와 궁합 최상, 독립 확장 | 중간재 중복 생산 가능 |
| **수직 타워(Vertical Tower)** | 공간 제약, 미관, 노드 밀집 지역 | 벨트 길이 단축, 층=공정 단계로 가독성 | 층당 수평 면적은 여전히 필요, 좁은 단일 기둥 공장은 고티어에서 비현실적 |

- Factorio 대비 메인 버스가 약한 이유(커뮤니티 합의): ①수직 공간이 열려 있어 중앙 분배 필요성이 낮고, ②건물 수가 Factorio의 약 1/4 수준이며, ③아이템이 보통 **2~4개 레시피**에서만 쓰여 재사용 폭이 좁다.
- 실무 주류: **자원 노드 근처에서 1차 가공(잉곳·판·로드) → 완제품/중간재만 기차·드론으로 중앙 집결.** 나무위키도 "모든 생산라인을 한 군데에 몰아 최적화시키는 건 매우 안 좋은 생각"이라며 확장 공간 소실을 이유로 든다.

### 2. 매니폴드 vs 로드 밸런서 — 실제 결론

- **포화 후에는 두 방식의 처리량이 동일하다.** 차이는 오직 **기동 시간(saturation time)** 과 **건설 비용/공간**뿐이다.
- 매니폴드가 성립하는 조건(공식 위키): "입출력 아이템 속도가 충분하고 **컨베이어 처리량에 의해 제한되지 않는 한**, 충분한 시간이 지나면 모든 기계가 100%로 돌아간다."
  → 즉 **총 소요량 > 벨트 1개 용량**이면 매니폴드는 실패한다. 이때가 밸런서 또는 **인젝티드 매니폴드**(각 병합 전 스마트 분배기로 처리량 손실 방지)를 쓸 지점이다.
- 밸런서를 쓸 곳: **기차역 입출력, 저장소 배열, AWESOME 싱크**, 즉시 만가동이 필요한 곳, 비대칭 비율 분배.
- 밸런서의 함정: 2·3 이외의 소인수(예: 5, 7)는 완전 밸런서가 안 나와 **올림 후 미사용 출력을 루프백**해야 하는데, 이 루프백이 **전체 처리량을 깎는다.** 손실을 막으려면 루프백을 다시 분배기/병합기로 균등 재분배해야 한다 — 복잡도가 급증한다.
- **매니폴드 기동 가속 = 프라이밍(priming).** 정론화된 기법: "펌프 → 버퍼 → 밸브" 순으로 저장고에 미리 자재를 쌓아두고, 스마트 분배기(유체는 밸브)를 닫아두었다가 개방해 **정상 공급률보다 빠른 속도(예: 480/min)로 버퍼를 채운다.** 버퍼가 차면 평형에 도달하며, 이후 정상 속도로 떨어져도 100% 유지.
- 대안: **언더클럭**으로 각 기계 소요량을 낮춰 전 기계가 균일 가동하게 만든다(예: 200/min 벨트에 30/min짜리 10기 → 66%로 언더클럭). 전력 효율도 함께 개선된다.

### 3. 층 분리 관행

- 제약이 강한 순서로 고정하라: **배관 > 생산 > 버스.** 배관은 양정(펌프 Mk1 22m)이라는 하드 제약이 있고, 초과 시 +2~3m에서 유량이 0이 되므로 층고를 배관 기준으로 먼저 잡는 것이 안전하다.
- 커뮤니티 관행 예시: 1층 물류/HUB/저장 → 2층 제련 → 3층 이상 생산, **"N층 아이템을 쓰는 것은 N+1층에 짓는다"** 규칙. 또는 **2개 층마다 물류 전용 층(예: 2.5층)** 을 끼워 스파게티를 차단.
- 수직 이송은 **1~2개의 라이저(riser) 기둥으로 집중**하고, 외벽을 따라 1×1 또는 2×2 타워를 세워 자재를 올린다.
- 층 바닥은 **1m 수직 단위**로 배치해야 리프트가 정확히 안착한다(월드 그리드 수직 스냅이 1m).
- 벽은 마지막에. "닫힌 방을 먼저 만들고 그 안에 기계를 넣지 마라. 넓은 공간에 파운데이션 깔고 전체 셋업을 먼저 완성한 뒤 벽을 세워라."

### 4. 블루프린트 모듈 설계 요령

- **가장자리 정렬**: 디자이너 내부 치수가 32/40/48m로 전부 8의 배수이므로 파운데이션을 가장자리에 딱 맞춰 깔면 스탬프끼리 이음매 없이 붙는다. **기둥은 경계에 걸쳐도 저장되므로** 경계면 정렬 가이드로 쓸 수 있다.
- **좌우 반쪽 분할**: 벨트/스플리터가 경계를 넘어야 할 때, 모듈을 좌반/우반으로 나눠 각각 반쪽 스플리터를 배치하고 두 스탬프가 만나면 완전한 연결이 되게 한다. 입력은 한쪽 가장자리, 출력은 반대쪽 가장자리로 **방향 규약을 고정**하면 베이가 자기 급전선을 가로지르지 않는다.
- **4층 적층 기법**: 1층을 수동으로 만들어 블루프린트로 저장 → 같은 디자이너 안에서 그 블루프린트를 기존 건물 위에 배치 → 2층 → 반복 → 전체를 다시 저장. 1개 층 노력으로 4층 모듈 완성. **하위 등급 BP를 상위 등급 디자이너에 넣는 것은 공식 지원**되므로 Mk1 모듈을 Mk3 안에서 조합하는 방식이 정석이다.
- **저장 후 철거 시 자재 회수**: 디자이너에서 철거하면 자재가 보관함 → 인벤토리 순으로 100% 돌아온다. 일반 철거도 100% 환급이므로 **모듈 시제품을 만들고 뜯는 비용은 0**이다. 반복 설계를 두려워할 이유가 없다.
- **베이 간 여유 레인**: 베이 사이에 **파운데이션 1장 분량의 빈 레인**을 두어 벨트·스플리터·통로로 쓴다. 나중에 기계를 추가할 때 아무것도 뜯지 않아도 된다.
- **오토커넥트(R) 16m**를 전제로 모듈 입출력 포트를 서로 16m 이내에 오도록 설계하면 스탬프 후 배선 작업이 사라진다.

### 5. 앱 데이터 계층에 바로 쓸 파생 규칙

- 기계 → 최소 타일: `Smelter 1×2`, `Constructor 1×2`, `Assembler 2×2`, `Manufacturer 3×3` (타일 = 8m).
- 모듈 크기 검증: 블루프린트 내부 치수 / 8 = 사용 가능 타일 수 (Mk1 4, Mk2 5, Mk3 6).
- 벨트 등급 선택: `필요 처리량 ≤ {60,120,270,480,780,1200}` 중 최소값.
- 매니폴드 성립 판정: `기계수 × 기계당소요량 ≤ 벨트등급처리량` 이면 매니폴드 가능, 아니면 인젝티드 매니폴드/밸런서.
- 펌프 필요 개수: `ceil(총 상승고 / 20)` (Mk1 권장치 기준, 실제 22m지만 마진 확보), 수평 구간 손실 1.2~1.5m 별도 고려.

**미해결 항목(추가 조사 필요)**

1. 생산 건물별 내부 입력/출력 버퍼의 정확한 아이템 수 — 매니폴드 포화 시간 계산식의 핵심 입력값인데 1차 출처가 없다.
2. 매니폴드 포화 시간의 검증된 공식 또는 실측 데이터셋 (기계 수 × 버퍼 × 공급률 함수).
3. 병합기(Merger)의 정확한 처리량 상한 — 분배기는 2000/min으로 확인했으나 병합기 수치는 확인 못 함.
4. Update 1.2에서 블루프린트/스냅 관련 "수정된 버그"의 구체 목록 — 패치노트 1.2.0.0 본문에서 레이아웃 관련 변경은 파이프라인 T자 분기 외에 확인되지 않았고, 1.2.2.x 핫픽스는 미확인.
5. 나무위키가 제시한 "컨베이어 적층 한 층당 2미터" 관행의 공식 근거 — 벨트 자체 두께 기준인지 실용 관행인지 불명.
6. Mk.2/Mk.3 디자이너의 실측 수용량(기계 대수) — Mk.1의 4×4 데이터만 커뮤니티 보고를 확보했다.
