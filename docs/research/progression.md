# 마일스톤 진행 최적화 (Milestone Progression Optimization)

> 기준 버전: **Update 1.2** (2026-06-02 정식, 1.2.2.2). 1.0/1.1 대비 변경점은 본문에 명시.
> 1차 출처: 공식 위키(satisfactory.wiki.gg). 교차검증: 나무위키, Steam 가이드/토론, 커뮤니티 공략, 한국 커뮤니티(arca.live, dcinside).

## 요약

- 진행은 **HUB 마일스톤(수직)** 과 **프로젝트 어셈블리(Project Assembly) 단계(수평 게이트)** 의 이중 구조다. 티어 0 완료 → 티어 1·2 개방, 이후 모든 티어는 스페이스 엘리베이터(Space Elevator) 납품으로만 열린다. **티어 내부 순서는 자유**이므로 최적화 여지는 전부 "티어 안에서 무엇을 먼저 미느냐"에 있다.
- 난이도 곡선의 실제 변곡점은 **Phase 1 → Phase 2**다. Phase 1은 스마트 플레이팅(Smart Plating) 50개(조립기 1대 25분)인데 Phase 2는 스마트 플레이팅 1,000 + 다목적 프레임(Versatile Framework) 1,000 + 자동 배선(Automated Wiring) 100으로 **20배 점프**한다. 이 지점이 "손조립 졸업 시험"이다.
- 초반 3대 병목은 **나사(Screw) → 콘크리트(Concrete) → 전력(Power)** 순으로 온다. 특히 나사는 표준 레시피 기준 Phase 2 스마트 플레이팅 1,000개만으로 **37,000개**가 필요하다(계산 근거 아래).
- 커뮤니티가 가장 많이 접는 구간은 두 곳: **티어 3 진입 전(전력 트립 반복)** 과 **티어 5~6(석유·복잡도·전력 급증 + MAM 연구 부족)**. 한국 커뮤니티는 후자를 명시적으로 "여기서 접는 사람이 꽤 많다"고 기록한다.
- 1.2는 진행 비용 자체를 바꾸지 않고 **게임 모드(Game Modes)** 로 배수 조절 옵션(스페이스 엘리베이터 0.25~100×, 레시피 비용 0.25~2×, 전력 소비 0.25~5×)을 추가했다. 도전과제를 끄지 않는다. → 앱은 이 배수를 **1급 파라미터**로 취급해야 한다.

**파생 계산(표준 레시피 기준, 위 수치로부터 산술 도출):**
- Phase 1(스마트 플레이팅 50) = 강화 철판 50 + 로터 50 = 나사 **600 + 1,250 = 1,850개**. 조립기 1대 25분.
- Phase 2의 스마트 플레이팅 1,000 = 강화 철판 1,000 + 로터 1,000 = 나사 **12,000 + 25,000 = 37,000개**. 제작기(40/분) 1대로는 **925분(≈15.4시간)**.
- → 대체 레시피(봉합 철판 + 강철 로터)를 확보하면 이 37,000개가 **0**이 된다. 초반 하드 드라이브 우선순위가 왜 "나사 제거"에 몰리는지의 정량적 근거.

마일스톤이 직접 요구하는 나사: 티어1 현장 연구 300 + 티어2 부품 조립 500 + 장애물 제거 500 = **1,300개**.

**정합 비율(위 수치에서 직접 도출):**
- 컨베이어 Mk.1(60/분) ÷ 석탄 15/분 = **벨트 1줄당 석탄 발전기 정확히 4대**. → 8대 라인을 깔려면 Mk.2(120/분) 필수 = **물류 Mk.2(티어2)를 석탄 발전 전에 뚫어야 한다**.
- 급수 추출기 3대(360 ㎥/분) = 석탄 발전기 8대(360 ㎥/분). **정확히 일치**(위키 명시).
- 파이프라인 Mk.1(300 ㎥/분) ÷ 45 = **6대**가 단일 파이프 한계(위키 본문은 "6~7대"로 서술).

**그리드 트립 규칙:** 소비 > 생산이고 저장 전력이 0이면 **그리드 전체가 정지**하며, 전신주나 발전기의 레버를 **수동으로 내려 리셋**해야 한다. 리셋 전에 발전기를 추가하거나 일부 구역 케이블을 끊지 않으면 즉시 재트립. 호버팩(Hoverpack)은 **100 MW를 소모하면서 전력 그래프에 표시되지 않으므로** 소규모 그리드 리셋 전 반드시 해제. (wiki.gg Power)

## 설계에 주는 시사점

1. **진행 그래프는 DAG로 모델링하고 게이트는 Phase 5개로만 표현한다.** 티어 내부는 순서 자유이므로 앱은 "정답 순서"가 아니라 **우선순위 점수**를 제시해야 한다. 점수 축: ①처리량 해금(벨트/채굴기) ②전력 안정성 ③대체 레시피 풀 개방 ④단순 편의.

2. **"목표 물량 → 필요 원자재" 역산기가 핵심 기능이다.** C·D절이 보여주듯 사용자가 놀라는 지점은 마일스톤 표시 비용이 아니라 **중간재 트리를 펼쳤을 때의 총량**이다. "Phase 2 스마트 플레이팅 1,000 → 나사 37,000" 같은 수치를 **선제 경고**로 노출해야 가치가 있다.

3. **대체 레시피 보유 여부를 계산기의 토글로 둔다.** 봉합 철판 + 강철 로터를 켜면 나사 소요가 37,000 → 0. 이 델타 자체가 "다음에 뭘 해야 하나"의 답이다.

4. **전력은 정수 비율 문제로 다뤄라.** 벨트1줄=석탄4대, 급수3대=발전8대, 파이프Mk.1=발전6대. 사용자가 입력한 발전기 수에 대해 **정확히 맞아떨어지는 모듈 크기**(예: 8대 모듈)를 추천하는 것이 실전적이다. 여유 전력 20% 확보는 커뮤니티 합의.

5. **1.2 게임 모드 배수를 데이터 계층 최상위 파라미터로 노출한다.** `spaceElevatorCostMultiplier`(0.25~100), `recipeCostMultiplier`(0.25~2), `powerConsumptionMultiplier`(0.25~5). 하드코딩 요구량 테이블은 반드시 이 배수를 곱해 표시.

6. **티어 3 이전은 "임시 기지" 라벨을 붙여라.** 다수 출처가 "석탄 발전 해금 전에는 영구 기지를 짓지 말라"로 일치. 초반 레이아웃 최적화를 권하는 UX는 역효과다.

7. **MAM 진행도를 티어 진행도와 나란히 표시하라.** 대체 레시피가 티어 게이팅되므로 "하드 드라이브 N개 보유 / 현재 티어에서 풀에 들어온 유용 레시피 M개" 뷰가 실제 의사결정에 쓰인다.

8. **경고 룰 엔진 후보**: ①Mk.1 벨트에 순수 노드 Mk.1 채굴기 연결(120 > 60) ②석탄 발전기 5대 이상을 Mk.1 벨트 1줄에 연결 ③석탄 발전기 7대 이상을 파이프 Mk.1 1줄에 연결 ④콘크리트 생산 15/분 이하로 티어4 진입 ⑤전력 여유 <10% ⑥나사 소모 레시피만 보유한 채 Phase 2 착수.

### 초보가 실제로 리스타트하게 되는 원인 Top 5 (커뮤니티 종합)

1. **첫 기지를 너무 일찍 확정** — 첫 철 노드 옆에 영구 기지를 지었다가 석탄·석유·알루미늄이 전부 멀어 물류 붕괴. (Steam 토론, GameRant, 한국 커뮤니티 공통)
2. **스파게티 벨트 → 확장 불가** — 벨트는 스케일하지 않는다. 장거리는 열차(티어6)가 답인데 그 전에 맵 전체에 벨트를 깔아버림. 500 m 초과 구간은 열차 권장. (Steam 가이드)
3. **전력 그리드 반복 트립** — 소비가 생산에 근접한 상태로 운영 → 전체 정지 → 수동 리셋 지옥. 호버팩 100 MW 미표시 함정 포함. (wiki.gg Power, jeu.video)
4. **Phase 2 물량 앞에서 정지** — Phase 1 대비 20배 점프를 손조립/저속 라인으로 넘으려다 소진. 나사·강철 병목이 여기서 폭발(C절 37,000개). 
5. **티어 5~6 벽** — 석유 진입(플라스틱·고무 비율, 부산물 처리), 공정 복잡도 급증, 전력 소비 급등, **MAM 연구 부족으로 인한 편의성 부재**가 동시에 온다. 한국 커뮤니티가 "여기서 접는 사람이 꽤 많다"고 명시. (arca.live 티어별 공략)

(메타 원인) **완벽주의형 리스타트 증후군** — "더 잘할 수 있었는데"로 인한 자발적 재시작. Steam에 전용 토론 스레드가 존재할 만큼 흔하다.
