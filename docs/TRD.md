### 2.1 스택 선택 기준 (심사 렌즈)
1. **5년 유지보수 비용** — 의존성이 썩는 속도, 빌드가 깨질 위험
2. **실사용 맥락** — 초기 로딩, 오프라인, 작은 화면
3. **요구 적합성** — 맵 오버레이·재귀 계산기·상태 영속·세이브 파싱

## 3. 성능 요구

| ID | 지표 | 목표 | 측정 조건 |
|---|---|---|---|
| P-1 | LCP (첫 화면) | < 1.5초 | Fast 3G, 중급 모바일 |
| P-2 | 전체 로딩 | < 3초 | 같음 |
| P-3 | 초기 JS 페이로드 | < 150 KB (압축 후) | 랜딩 + 첫 화면 |
| P-4 | 이미지 총량 | < 800 KB | 맵 2장 + 아이콘 27개. 현재 648 KB |
| P-5 | 계산기 응답 | < 100 ms | 10단계 깊이 체인 |
| P-6 | 맵 확대·이동 | 60 fps | 중급 모바일 |
| P-7 | 세이브 파싱 | UI 블로킹 0 ms | Web Worker 필수 |
| P-8 | INP | < 200 ms | 전 인터랙션 |

### 3.1 이미지 전략
- 포맷: WebP (AVIF는 용량 이득 대비 인코딩 복잡도 검토 후 결정)
- 맵: 원본 1600×1600 유지 (확대 시 화질 필요). `loading="lazy"`, `decoding="async"`
- 아이콘: 128px WebP, 알파 보존
- 반응형: 맵은 `srcset`으로 저해상도 대안 제공 검토

## 4. 데이터 요구

### 4.1 데이터 분리 원칙 (확정)
| 구분 | 내용 | 특성 |
|---|---|---|
| **게임 데이터** | 아이템·레시피·건물·마일스톤·노드 좌표 | 읽기 전용, 앱과 함께 배포, 버전 = 게임 버전 |
| **사용자 데이터** | 마일스톤 체크·대체레시피 확보·공장 상태·계산기 설정 | 읽기·쓰기, 로컬 영속, 스키마 버전 관리 필수 |

두 계층은 **절대 섞지 않는다.** 게임 데이터 갱신이 사용자 데이터를 훼손해서는 안 된다.

### 4.2 게임 데이터 규모 (추정)
아이템 ~160종 · 레시피 ~300종 · 건물 ~100종 · 마일스톤 ~45개 · 자원 노드 ~460개 + 자원정 118 + 간헐천 31 + 슬러그 1242 + 하드드라이브 118. 직렬화 시 1~5 MB 추정.

### 4.3 데이터 신뢰도 스키마 (확정)
모든 게임 데이터 항목은 다음을 갖는다:
```
{ "value": ..., "source": "URL 또는 출처명", "confidence": "verified" | "consensus" | "disputed" }
```
- `verified` — 공식 데이터 덤프 또는 공식 위키로 확인
- `consensus` — 복수의 독립 출처가 일치
- `disputed` — 출처 간 불일치. **앱 핵심 계산에 사용 금지.** UI에서 시각적으로 구분

### 4.4 사용자 데이터 요구
| ID | 요구 |
|---|---|
| D-1 | 최상위에 `schemaVersion` 필드를 둔다 |
| D-2 | 스키마 변경 시 마이그레이션 함수를 제공한다. 마이그레이션 없는 파괴적 변경 금지 |
| D-3 | 마이그레이션 실패 시 원본을 보존하고 사용자에게 알린다 |
| D-4 | 전체를 JSON으로 내보내고 가져올 수 있다 |
| D-5 | 세이브 임포트 등 대량 변경 전 자동 백업한다 |

| 대상 | 요구 |
|---|---|
| 브라우저 | Chrome/Edge 최신 2개 버전, Firefox 최신 2개, Safari 최신 2개 |

### 5.1 모던 웹 기능 채택 기준
Baseline 상태를 확인하고 `지금 써도 됨 / 폴백 필요 / 아직 이르다`로 판정한다. 판정표는 `docs/research/design-web-2026.md`. 폴백 없이 쓰는 기능은 위 브라우저 범위에서 **전부 지원되어야 한다.**

## 8. 품질

### 8.1 테스트
| 대상 | 방식 | 수준 |
|---|---|---|
| 생산 체인 계산 | 단위 테스트. 알려진 비율로 검증 (예: 모듈러프레임 2/분 → 철광 정확값) | MUST |
| 순환 레시피 처리 | 단위 테스트. 무한루프 없음 확인 | MUST |
| 데이터 무결성 | 스크립트. 모든 레시피의 참조 아이템 존재, confidence 필드 존재 검증 | MUST |
| 사용자 데이터 마이그레이션 | 단위 테스트. 이전 버전 → 최신 변환 | MUST |
| 전역 스크롤 접근성 | 빌드 산출물을 Chromium으로 열어 키보드·해시·동적 reduce·뒤로가기 복원 검증 | MUST |
| 세이브 파서 | 실제 세이브 파일로 통합 테스트 | SHOULD |
| 접근성 | 자동 검사 + 키보드 수동 확인 | SHOULD |

### 8.2 CI
- 푸시 시 데이터 무결성 검사와 단위 테스트 실행
- `main` 브랜치 → GitHub Pages 자동 배포
