- 작성일: 2026-08-19
- 성격: **실행 지시서**. 여기 적힌 값은 그대로 CSS 토큰/컴포넌트로 옮긴다. "적절히", "세련되게" 같은 판단 유예 표현은 이 문서에 없다.

## 01. 포지셔닝 한 문장

> **satisfactory-ops는 Satisfactory를 혼자 굴리다가 공장을 세 번쯤 갈아엎은 한국어 플레이어에게, 다음에 무엇을 지어야 하는지와 지금 이 배치가 나중에 왜 막히는지를 알려주는 웹 플레이북이다.**

이 문장에서 빼면 안 되는 요소: `혼자`(협업 도구 아님), `한국어`(1차 언어), `다음에 무엇을`(순서), `나중에 왜 막히는지`(예측). 카피 변주는 허용하되 이 네 요소 중 하나라도 빠지면 반려.

**무엇이 아닌가** (랜딩과 README에 명시할 것):

- 최적해를 뱉는 계산기가 아니다. 계산기는 이미 충분히 많다(satisfactory-calculator, SatisfactoryTools, FICSIT Planner).
- 세이브 파일 에디터가 아니다. 게임 파일을 건드리지 않는다.
- 공식 도구가 아니다. Coffee Stain과 무관한 개인 팬 프로젝트다.

## 02. 디자인 컨셉 — "FICSIT 현장 배포 문서"

### 컨셉 한 줄

게임 속 FICSIT이 신입 파이오니어에게 던져줬을 법한 **현장 배포용 작업 지시서**. 종이 문서의 조판 규칙(번호·규칙선·라벨-값 표·각주)을 웹으로 옮기고, 게임 HUD의 색 운용 원칙(중성색 90% + 경고색 10%)을 그대로 따른다.

### 왜 이 컨셉인가

근거 문서에서 확인된 두 가지가 이 컨셉을 강제한다.

1. FICSIT의 아이덴티티는 "오렌지의 정확한 hex"가 아니라 **오렌지+차콜의 사용 비율**에 있다. 팬 사이트 실패는 예외 없이 오렌지를 배경으로 쓴 경우다.
2. 세계관 톤은 밝은 기업 카피가 아니라 **관료적 안전제일주의 + 블랙코미디**다("Exploit"의 이중의미, 직원을 "FICSIT property"로 호칭).

문서 은유는 이 앱의 기능(체크리스트·단계도·레퍼런스 표)과도 형태가 일치한다. 억지 차용이 아니다.

### 차용하는 것 (허용)

| 요소 | 구체 실행 |
|---|---|
| 오렌지+차콜 조합 | 팔레트 03에 정의. 오렌지는 포인트 전용 |
| 산업 문서 조판 | 섹션마다 상단 1px 풀폭 규칙선 + 모노스페이스 번호(`01` ~ `08`) 좌측 정렬 |
| 사양표 형식 | 정보는 카드가 아니라 **라벨-값 2열 표**로. 좌열 모노 소형 라벨(대문자/자간 +0.08em), 우열 값 |
| 각주 문화 | 불확실한 데이터에 `*` 각주 + 하단 출처 블록. 근거 문서의 "미확인은 미확인으로" 원칙을 UI로 계승 |
| 데드팬 안전문 톤 | 마이크로카피 한정. 예: 빈 상태 → "배치된 설비 없음. FICSIT은 유휴 상태의 파이오니어를 기록합니다." |
| 자원 색상 | 게임 텍스처 유래값을 자원 칩 토큰으로 (03 하단) |

### 차용하지 않는 것 (금지 — 위반 시 반려)

| 금지 | 이유 |
|---|---|
| FICSIT "V" 로고 심볼의 재현·변형·오마주 | 상표 심볼 직접 모사. 색 조합 모사와 달리 방어 논리가 없다 |
| 게임 UI 아이콘·아이템 아이콘 원본 애셋 사용 | 저작물 직접 재배포 |
| 게임 스크린샷을 히어로 배경/장식으로 깔기 | 저작권 + 시각적으로 촌스러움(텍스트 가독성 파괴) |
| 제품명·도메인·헤더 로고에 "FICSIT" 또는 "Satisfactory"를 단독 브랜드처럼 배치 | 공식 오인. 제품명은 `satisfactory-ops`, 헤더 표기는 워드마크만 |
| "표준", "규격", "공식 시스템" 류 자칭 명명 | `SatisfactoryColors`의 "FICSIT Standard Industrial Color System(SICS)" 사례 — 비공식인데 공식처럼 읽혀 정보 신뢰도를 오염시킨다 |
| 세계관 톤을 **정보 전달 문장**에 적용 | 유머는 마이크로카피(빈 상태, 각주, 404, 툴팁)에만. 수치·경고·설명 문장은 100% 평문 |

### 맵 이미지 처리 (별도 결정 사항)

1안(채택): **자체 벡터 지형도**. 게임 맵 스크린샷을 쓰지 않고, 고도 등고선 + 바이옴 경계 + 자원 노드 좌표만 SVG로 단순화해 직접 그린다. 저작권 리스크 0, 그리드 오버레이와의 정합성도 높고, 문서 은유("측량도")와도 맞는다.

2안(대안): 커뮤니티 맵 타일 사용. 반드시 라이선스 명시 확인 후, 출처를 맵 하단에 상시 표기. **확인 전 사용 금지.**

### 법적 고지 (푸터 고정, 삭제 불가)

> satisfactory-ops는 비공식 팬 제작 프로젝트입니다. Coffee Stain Studios와 제휴·승인 관계가 없습니다. Satisfactory 및 관련 상표는 각 소유자의 재산입니다.

## 03. 팔레트

색공간은 `oklch()`를 1순위로 쓰되(사용률 93~95%, 근거: design-web-2026), **HEX를 정본으로 정의**하고 필요 시 `color-mix()`로 파생한다. 아래 대비비는 전부 WCAG 2.x 공식에 따라 직접 계산한 값이다.

### 오렌지 사용 규칙 (강제)

1. **10% 룰**: 뷰포트 1화면당 오렌지로 채색된 면적이 전체의 10%를 넘지 않는다. (게임 커뮤니티가 정리한 팩토리 배색 원칙과 동일 — 근거 문서 2절)
2. 헤더 배경, 풀블리드 배너, 히어로 배경에 오렌지 **금지**.
3. **화면당 오렌지 채움 버튼 1개**. 나머지 버튼은 `--line-strong` 1px 아웃라인 + `--ink`.
4. 오렌지 그라디언트 금지. 오렌지 글로우/블러 금지.
5. 다크모드 기본 진입. `prefers-color-scheme`을 따르되 미지정 시 다크. (게임과 알트탭하며 쓰는 도구라 밝은 화면이 눈부시다.)

### 자원 색상 토큰

게임 텍스처 스포이드값을 정본으로 두되, **상당수가 거의 검정이라 그대로는 UI 칩으로 못 쓴다**. 따라서 각 자원에 `raw`(정체성)와 `ui`(가독성 보정) 두 값을 둔다. `ui` 값은 다크 배경 기준 최소 3:1을 만족하도록 명도만 올린 값이다.

| 자원 | `raw` (게임 유래) | `ui` (칩/범례용) |
|---|---|---|
| 철광석 | `#989FA9` | `#989FA9` (보정 불필요) |
| 알루미늄 | `#D2D3D4` | `#D2D3D4` |
| 실리카 | `#D8DDE7` | `#D8DDE7` |
| 석영 | `#767676` | `#8E8E8E` |
| 유황 | `#867F7D` | `#9C9491` |
| 석탄 | `#0B0B19` | `#5A5A78` |
| 원유 | `#161718` | `#6A6E73` |
| 고무 | `#202020` | `#6E6E6E` |
| 물 | `#1662AD` | `#4B93DE` |
| 플라스틱 | `#3091E6` | `#3091E6` |
| 우라늄 | `#88D288` | `#88D288` |
| 황산 | `#FFF03A` | `#FFF03A` |
| 중유 잔여물 | `#9021B8` | `#B455D8` |
| 연료 | `#F89800` | **사용 금지 — 아래 R1 참조** |

**규칙 R1 (연료 색 충돌)**: 연료 `#F89800`과 터보연료 계열은 브랜드 `--accent`와 육안 구분이 안 된다. 이 두 자원은 **색만으로 표기하지 않는다.** 칩에 반드시 텍스트 라벨을 병기하고, 색은 `--ink-2` 중성으로 처리한다.

**규칙 R2 (미확인 자원)**: 구리, 석회석, 보크사이트, 우라늄 원광, SAM 계열은 근거 문서에서 hex를 **확보하지 못했다**. 값을 지어내지 않는다. 확정 전까지 `--res-unverified: #7A7A7A`(중성 회색) + 칩에 `*` 각주를 달고, 각주에 "색상 미확정"이라고 쓴다. 카테리움은 스와치명(Gray)과 위키의 시각 설명(금색/적갈색)이 불일치하므로 동일 처리한다.

**규칙 R3**: 자원 색은 **정보 전달용 보조**일 뿐, 단독 인코딩 금지. 색맹 대응으로 항상 텍스트 라벨 또는 형태를 함께 쓴다.

## 04. 타이포그래피

### 3역할 배정

| 역할 | 폰트 | 이유 |
|---|---|---|
| **표시용(Display)** — 히어로/섹션 헤드라인 | `IBM Plex Sans KR` (OFL, 700) | 엔지니어링 문서를 위해 설계된 서체라 "산업 문서" 컨셉과 정합. 무엇보다 **Pretendard/Inter와 골격이 달라서** 본문과 진짜 위계가 생긴다. 근거 문서가 지목한 최상위 AI 지문이 "단일 폰트로 위계 없이 통일"이다 |
| **본문(Body)** — 모든 설명·UI 텍스트 | `Pretendard Variable` | KRDS가 국문·영문 공통 기본 서체로 지정한 사실상 표준. 한글 렌더링 품질과 가변 축(400~700) 확보 |
| **수치용(Numeric)** — 분당 생산량, 기계 대수, 오버클럭 % | `IBM Plex Mono` (400/500) | tabular figure 필수(표에서 자릿수 정렬). Display와 같은 Plex 패밀리라 3폰트를 써도 화면이 흩어지지 않는다. 슬래시 제로로 0/O 혼동 제거 |

**폴백 스택 (전부 명시)**

```css
--font-display: "IBM Plex Sans KR", "Pretendard Variable", Pretendard, -apple-system, "Segoe UI", "Malgun Gothic", sans-serif;
--font-body:    "Pretendard Variable", Pretendard, -apple-system, BlinkMacSystemFont, "Segoe UI", "Malgun Gothic", "Apple SD Gothic Neo", sans-serif;
--font-mono:    "IBM Plex Mono", ui-monospace, SFMono-Regular, Consolas, D2Coding, monospace;
```

### 웹폰트 vs 시스템 스택 — 결정

**결론: 역할별로 다르게 간다.** 전부 웹폰트도, 전부 시스템도 아니다. 한글 완성형 음절만 11,172자라 무비판적 self-host는 즉시 수백 KB를 태운다(근거 문서 3절).

| 역할 | 방식 | 예산 | 근거 |
|---|---|---|---|
| Display | **빌드타임 정적 서브셋**. 랜딩+앱 헤드라인에 실제 등장하는 문자만 추출해 WOFF2 생성 | ≤ 25KB | 헤드라인 문자 종류는 100자 미만. 개성 획득 대비 비용이 가장 싸다. `<link rel="preload">` + `font-display: block`(헤드라인이 두 번 그려지면 더 싸구려로 보인다) |
| Body | **다이나믹 서브셋 CDN**(Pretendard 가변 다이나믹 서브셋) + 시스템 폴백 | 초기 페인트 차단 0 | 본문 문자 종류는 예측 불가. `font-display: swap`. **주의: 근거 문서에 실제 KB 수치가 확보되지 않았다 — 구현 시 GitHub Releases에서 자산 크기를 직접 측정하고 이 표를 갱신할 것** |
| Numeric | **라틴 서브셋만** self-host (숫자·기호와 `/min`, `x`, `%`에 필요한 ASCII) | ≤ 10KB | 한글 글리프 불필요 |

**총 폰트 예산: 첫 화면 차단 리소스 ≤ 35KB (Display + Numeric). Body는 비차단.**

**CLS 방어**: 폴백 폰트에 `size-adjust`를 지정한다. 정확한 조정값은 실측이 필요하므로 **구현 시 Malgun Gothic / Apple SD Gothic Neo 기준으로 측정해 채워 넣을 것**(추정값을 미리 박아두지 않는다).

### 스케일 (KRDS 기준, PC / 모바일)

| 레벨 | PC | 모바일 | line-height | letter-spacing | 폰트 |
|---|---|---|---|---|---|
| Display | 60px | 40px | 1.15 | **-0.015em** | display 700 |
| H1 | 40px | 28px | 1.25 | -0.01em | display 700 |
| H2 | 32px | 24px | 1.3 | -0.005em | display 700 |
| H3 | 24px | 22px | 1.4 | 0 | body 600 |
| Body L | 19px | 19px | 1.7 | 0 | body 400 |
| **Body M (기본)** | **17px** | **17px** | **1.7** | **0** | body 400 |
| Body S | 15px | 15px | 1.6 | 0 | body 400 |
| Caption / 각주 | 13px | 13px | 1.6 | 0 | body 400 |
| 소형 라벨 | 12px | 12px | 1.2 | **+0.08em** | mono 500, 대문자 |
| 수치(인라인) | 상속 | 상속 | 상속 | 0 | mono 500, `font-variant-numeric: tabular-nums` |

**자간 주석**: KRDS는 Display에 +1px을 권한다. 우리는 -0.015em으로 **의도적으로 반대로 간다** — KRDS 권고는 400~600 weight 전제이고, 우리 Display는 700이라 기본 자간이 이미 넓게 느껴진다. 본문 0em은 KRDS 그대로 따른다.

### 한글 조판 규칙

1. **좌측 정렬 고정.** 양끝 정렬 금지 — 국영문 혼용 비중이 높다(아이템명·수치가 영문/숫자).
2. 한글과 영문·숫자 사이에 **추가 공백을 넣지 않는다**(W3C 한국어 레이아웃 요구사항). `강화 철판 20개/분`(O), `강화 철판 20 개 / 분`(X).
3. 본문 컬럼 최대폭 `42em`(17px 기준 약 714px, 한글 40~45자). 초과 시 2단 또는 표로 전환.
4. 헤드라인에 `text-wrap: balance` 적용(전 주요 엔진 지원, 미지원 시 무시되어도 무해). `text-wrap: pretty`는 Firefox 미지원이라 **사용하지 않는다**.
5. 아이템 고유명은 **한국어(영문)** 병기를 첫 등장 1회만: `강화 철판(Reinforced Iron Plate)`. 이후 한국어만.

### 간격 스케일

4px 배수. `4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96`. 이 밖의 값 금지. 컨테이너 최대폭 `1200px`, 거터 `24px`(PC) / `16px`(모바일).

## 05. 랜딩페이지 섹션 구성

### 히어로 유형 결정: **라이브 데모형**

근거: 근거 문서가 정리한 판단 기준은 "제품을 한 문장으로 설명 가능한가 × 화면이 곧 셀링포인트인가"의 교차다. 우리는 (a) 신뢰 자산이 0인 신생 개인 프로젝트이고, (b) 만져보면 15초 안에 값어치가 증명되는 계산 도구다. 이 조합에서 라이브 데모가 최강이라는 것이 리포트의 명시적 결론이며, 특히 **실제로 동작하는 계산기가 증언보다 강한 신뢰 신호**다.

### 히어로 구체 사양

```
[중앙 정렬 영역, 상단 여백 96px]
  헤드라인 (Display 60px, 최대 2줄, text-wrap: balance)
    "강화 철판 20개/분. 지금 이 배치는 티어 5에서 막힌다."
  서브헤드 (Body L 19px, --ink-2, 1줄)
    "다음에 무엇을 지을지와, 지금 배치가 나중에 왜 문제가 되는지를 같이 봅니다."
  CTA 2개 (수평, 간격 12px)
    [주]   "플레이북 열기"   — --accent 채움, radius 4px
    [보조] "GitHub에서 보기" — --line-strong 1px 아웃라인
[여백 48px]
[라이브 위젯 — 풀폭, max-width 1080px, --surface, 1px --line]
```

**라이브 위젯 = 히어로 이미지다.** 스크린샷도 목업도 아니고 실물이다.

- 입력 2개: `만들 것`(셀렉트, 기본값 `강화 철판`), `목표`(숫자, 기본값 `20`/분)
- 출력: 즉시 렌더되는 생산 트리. 각 노드에 기계 종류 · **소수 대수**(`3.75대`) · 원료 분당 소모량.
- **결정적 차별점 — 각 노드 하단 한 줄 경고.** `--accent` 3px 좌측 보더 + Body S:
  > `제작기 3.75대 → 4대로 지으면 25% 유휴. 지금은 3대 + 오버클럭 125%가 벨트 여유까지 남깁니다.`
  이 한 줄이 포지셔닝 전체를 히어로 안에서 증명한다. 이 줄이 없으면 우리는 그냥 또 하나의 계산기다.
- 기술 요건: **네트워크 요청 0**. 히어로에 필요한 레시피 서브셋(약 40개)을 HTML에 인라인 JSON으로(gzip ≤ 8KB). 첫 입력에 대한 반응 지연 0ms.
- 접근성: 셀렉트/인풋에 `<label>` 명시, 결과 트리는 `aria-live="polite"`.
- LCP 대상은 텍스트다(히어로 이미지 없음). **목표 LCP < 1.5s.**

### 전체 섹션 (8개)

각 섹션 상단: 풀폭 1px `--line` 규칙선 + 그 아래 모노 12px 대문자 번호/라벨(`02 / 왜 다른가`). 좌측 정렬. 섹션 간 수직 여백 96px(PC) / 64px(모바일).

| # | 섹션 | 무엇을 보여주는가 | 형식 |
|---|---|---|---|
| 01 | 히어로 | 작동하는 계산기 | 위 사양 |
| 02 | 왜 다른가 | **같은 입력, 다른 출력**을 나란히. 좌: "기존 계산기의 답"(기계 대수 표) / 우: "우리 답"(순서 + 경고). 실제 텍스트로, 기능 비교표 아님 | 2열, 각 열 실물 텍스트 |
| 03 | 마일스톤 체크리스트 | 실제 앱 UI 스크린샷. **편집·합성 금지, 크롭만.** 티어 3 진행 중 상태 | 단일 이미지, 좌측 정렬, 1px `--line` 테두리 |
| 04 | 입지 선정 | 인터랙티브 미니맵(자체 벡터 지형도). 그리드 오버레이 토글 1개, 프리셋 핀 3개(초반 철·석탄·석유 거점). 팬/줌 없음 — 랜딩은 맛보기 | 인라인 SVG, 상호작용 2종만 |
| 05 | 공장 성장 단계도 | 4단계 토글(`1 → 2 → 3 → 4`). 클릭 시 배치가 실제로 확장되는 morph. **이 페이지의 유일한 볼거리 모션** | 인라인 SVG + 단계 버튼 4개 |
| 06 | 나머지 도구 | 생산 계산기 전체 화면 / 용어집 / 레퍼런스 표 — 스크린샷 3장 + 각 1~2문장 | **좌측 정렬 세로 리스트. 3열 아이콘 카드 그리드 금지** |
| 07 | 만든 사람과 현재 상태 | 실명 · 아바타 · GitHub 링크 · 왜 만들었는지 한 문단 · 데이터 출처와 대응 게임 버전 · "혼자 만들고 있음" 명시 · 최근 변경 5건 | 라벨-값 표 + 체인지로그 리스트 |
| 08 | 최종 CTA + 푸터 | 주 CTA 재노출 1회 + 법적 고지 | 좌측 정렬 |

### 소셜 프루프: **섹션을 만들지 않는다**

근거 문서의 결론을 그대로 집행한다. 후기 섹션 없음, 로고 월 없음, "10,000+ 사용자" 없음, 별점 배지 없음. **가짜 프루프는 발각 시 신뢰를 영구히 잃는다.** 대신 07번의 투명성(실명 + 데이터 출처 + 게임 버전 + 미확인 항목을 미확인이라 적는 태도)과 01번의 작동하는 계산기가 프루프를 대신한다. 실제 사용자 피드백이 한 줄이라도 생기면 그때 07번 하단에 실명으로 추가한다.

### CTA 구조

히어로 2개(주+보조) → 섹션 04·05 하단에 각 1개 텍스트 링크(`전체 지도 열기 →`) → 08번 풀폭 재강조 1개. **오렌지 채움 버튼은 화면당 최대 1개** 규칙을 스크롤 위치와 무관하게 유지.

## 06. 모션 원칙

원칙: **모션은 정보이거나, 없거나.** 장식적 모션 0개.

### 허용 (화이트리스트 — 이 목록 밖은 전부 금지)

| 대상 | 지속 | 이징 | 비고 |
|---|---|---|---|
| 호버/포커스 색 전환 | 90ms | `linear` | `color`, `background-color`, `border-color`만 |
| 체크박스 체크, 토글 상태 변화 | 120ms | `ease-out` | |
| 아코디언/디스클로저 열림 | 180ms | `ease-out` | `height` 대신 `grid-template-rows` |
| 계산 결과 갱신 | 200ms | `ease-out` | 동일문서 View Transitions로 **노드 위치 이동만**. 페이드인 금지 — 값이 바뀐 자리를 눈이 따라가게 하는 것이 목적 |
| **성장 단계도 단계 전환** | **300ms** | `ease-in-out` | 이 페이지 유일한 예외적 "볼거리". 공장이 어디서 어떻게 확장되는지가 곧 정보이므로 허용 |

### 금지 (전부 반려 사유)

- 스크롤 하이재킹, 스크롤 연동 애니메이션(`animation-timeline`) — 기능적으로도 Firefox 156+에서야 지원되고, 무엇보다 우리가 원하는 종류의 모션이 아니다
- 히어로 진입 시 요소 stagger 페이드인 / 슬라이드업
- 패럴랙스, 숫자 카운트업, 타이핑 효과, 무한 마퀴
- 글래스모피즘 블러, 방사형 글로우 펄스, 호흡하는 그림자
- `transform: scale()` 호버 확대 (카드·버튼 전부)

### 기술 판단 (2026 베이스라인 근거)

| 기능 | 판정 |
|---|---|
| 동일문서 View Transitions | **사용**. 사용률 90.21%, 3사 안정 채널 지원. 미지원 시 스냅 전환되도록 순수 progressive enhancement로 |
| MPA View Transitions | 사용 안 함 (Firefox가 `@view-transition` 무시) |
| Scroll-driven Animations | 사용 안 함 |
| CSS Anchor Positioning | 사용 안 함. 툴팁/팝오버는 `popover` 속성(Baseline 2025)으로 |
| `<dialog>` / `popover` | 사용 |
| Speculation Rules | 사용 안 함 (사실상 Chromium 전용) |

### `prefers-reduced-motion: reduce`

모든 `transition-duration`/`animation-duration`을 `0.01ms`로. **단 상태 변화 자체는 즉시 반영된다**(체크는 체크된다). View Transitions는 이 조건에서 비활성화.

| 10 | 다크모드 = 라이트의 단순 색 반전 | 라이트 = **문서**(콘크리트 웜 뉴트럴), 다크 = **현장 HUD**(청색 편향 차콜). 두 모드가 서로 다른 은유를 갖고, 03절 표대로 각각 독립 정의 |
| 11 | 접근성 디테일 누락(포커스 링 제거, 필수 표시 없음) | `:focus-visible { outline: 2px solid var(--accent); outline-offset: 2px; }` **제거 금지**. 필수 입력은 라벨에 `*` + `aria-required`. 대비비는 03절 계산값을 회귀 테스트로 고정 |
| 12 | 오렌지 도배(팬 사이트 최다 실패 유형) | 03절 10% 룰 + 화면당 오렌지 버튼 1개 |
| 13 | 목적 없는 로딩 스켈레톤/스피너 | 히어로 계산은 네트워크 0이므로 로딩 상태 자체가 없다. 앱 내 지연 200ms 초과 시에만 정적 텍스트("계산 중") |

## 08. 구현 검수 체크리스트

머지 전 아래를 순서대로 확인한다. 하나라도 실패하면 반려.

- [ ] 페이지 전체에서 `linear-gradient`/`radial-gradient` 검색 결과 **0건**
- [ ] `box-shadow` 사용처가 `dialog`/`popover` 외에 **0건**
- [ ] `border-radius` 값이 `2px`/`4px` 외에 **0건**
- [ ] 오렌지 계열 채색 면적이 첫 화면의 10% 이하, 오렌지 채움 버튼 1개
- [ ] 폰트 패밀리 3종 이외 사용 0건, 첫 화면 차단 폰트 ≤ 35KB
- [ ] `--ink` / `--ink-2` / `--ink-3` / `--accent-ink` / `--line-strong` 대비비가 03절 표와 일치(현재는 다크 한 벌만 구현)
- [ ] 히어로 위젯이 네트워크 차단 상태에서 정상 동작
- [ ] 히어로 위젯의 **경고 한 줄**이 실제 계산 결과에 따라 바뀐다(하드코딩 아님)
- [ ] `prefers-reduced-motion: reduce`에서 모든 모션 정지, 상태 변화는 유지
- [ ] 후기/로고월/사용자수 표기 0건
- [ ] 미확인 자원 색이 `#7A7A7A` + `*` 각주로 처리됨 (지어낸 hex 0건)
- [ ] FICSIT 로고 심볼·게임 원본 애셋 0건
- [ ] 푸터 법적 고지 존재
- [ ] 섹션 제목만 훑었을 때 이 앱이 무슨 앱인지 파악됨
- [ ] LCP < 1.5s, CLS < 0.1
