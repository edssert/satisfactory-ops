# ADR-0019 — 데이터는 JSON을 정본으로 두고, 검증·질의는 빌드 타임 SQL로 한다

- 상태: Accepted
- 날짜: 2026-08-19
- 관련: ADR-0012 (2단 데이터 파이프라인), `docs/research/layout-knowledge.md`

## 맥락

프로젝트 초기에 "전문적인 DB는 필요 없다"고 판단했다. 그 판단의 근거는 앱 런타임이었고,
그 부분은 지금도 유효하다:

- 데이터 총량 약 1 MB (아이템 750 · 레시피 872 · 건물 539 · 마일스톤 42 · 노드 626)
- 전부 읽기 전용. 쓰기·트랜잭션·동시성·다중 사용자가 없다
- 정적 사이트라 질의는 빌드 타임 또는 브라우저 메모리에서 끝난다
- 브라우저에 SQLite WASM을 보내면 약 1 MB가 추가된다 — 정적 플레이북에서는 손해다

바뀐 것은 **저작(authoring)과 검증** 쪽이다. 배치 설계 기능을 만들면서 손으로 큐레이션하는 표가
늘고 서로를 참조하기 시작했다:

- 기계별 벨트 접속부 위치 (게임 데이터에 없어 측정·가정해야 한다 — `layout-knowledge.md` §2.1)
- 배치 패턴 (모듈 규격, 층고, 통로 폭)과 그 출처
- 대체 레시피 우선순위 (티어별)
- 시작 부지 서술, 마일스톤 조언

이 표들은 전부 `source`와 `confidence`를 행마다 달아야 하고, 클래스 id로 게임 데이터를 참조한다.
JSON을 손으로 고치면 참조가 조용히 깨진다. 실제로 깨졌다 — 노드 데이터의 `철광석`과 게임의
`철 광석`을 한글 이름으로 조인해 화면에 "근처에 노드 없음"이 떴다.

또한 개발 중 관계 질의를 매번 `node -e`로 JSON을 훑어 쓰고 있었다. 반복되고 실수가 난다.

## 결정

**JSON을 정본으로 유지하고, 빌드 타임에 SQLite로 적재해 관계 검증과 개발용 질의에 쓴다.**

- 정본: `src/data/app/*.json` (파이프라인 산출물) + `src/data/curated/*.json` (사람이 쓴 것)
- 도구: Node 내장 `node:sqlite` (`DatabaseSync`). 외부 의존성 0, 브라우저로 나가지 않는다
- 산출: `.cache/game.db` (gitignore). 커밋하지 않는다 — JSON에서 언제든 다시 만든다
- 용도 두 가지
  1. **관계 검증**: 외래 키·중복·고아 참조를 SQL로 검사한다. 지금은 개별 스크립트에 흩어진 검사가
     선언적인 질의 한 벌이 된다
  2. **개발 질의**: `npm run db "select ..."` 로 데이터를 즉시 물어본다

## 왜 JSON을 정본에서 내리지 않는가

- **git diff가 읽힌다.** 데이터가 바뀌면 리뷰에서 무엇이 바뀌었는지 보인다. `.db`는 바이너리라 안 보인다
- **게임 업데이트 재생성이 정본을 덮어쓴다.** 정본이 DB면 파이프라인이 DB를 쓰고 사람이 쓴 값과
  섞인다. JSON은 생성물(`app/`)과 큐레이션(`curated/`)이 디렉터리로 갈라져 있다
- **런타임이 JSON을 그대로 쓴다.** Astro가 빌드 타임에 import한다. 중간 변환이 없다

## 왜 지금 SQL을 들이는가 (더 미루지 않는가)

큐레이션 표가 서로 참조하기 시작한 시점이 경계다. 표 하나짜리일 때는 손검사로 충분했고, 실제로
그렇게 해왔다. 포트 표가 들어오면 `(building_id, port_index)` 유일성, `building_id`의 존재,
`confidence` 값 제한 같은 것을 매번 손으로 쓸 수 없다.

## 결과

**좋아지는 것**
- 참조 무결성 검사가 선언적이 된다
- 개발 질의가 한 줄이 된다
- 새 큐레이션 표를 추가할 때 스키마가 강제된다

**나빠지는 것 / 비용**
- 빌드 단계가 하나 늘어난다 (수백 ms)
- 스키마를 JSON 구조와 나란히 유지해야 한다 — 두 곳을 고쳐야 하는 부담이 생긴다
  → 완화: 스키마는 `scripts/db-schema.sql` 한 파일에 두고, 적재기가 JSON 키를 그대로 매핑한다

**하지 않는 것**
- 서버 DB를 두지 않는다
- 브라우저에 DB를 보내지 않는다
- `.db`를 커밋하지 않는다
- 사용자 데이터(진행 상황)를 여기 넣지 않는다 — 그것은 계속 localStorage이고 별개 저장소다
