# ADR-0018: 표시·본문은 시스템 폰트, 수치용만 자체 호스팅한다

- **상태**: 채택
- **날짜**: 2026-08-19
- **관련 문서**: `docs/DESIGN-BRIEF.md` §04(타이포그래피) — 이 ADR이 그 절의 폰트 조달 계획을 개정한다
- **관련 결정**: ADR-0009(아키텍처), TRD S-3(런타임 외부 리소스 금지), TRD P-1~P-3(성능 예산)

## 맥락

디자인 브리프 §04는 3역할 폰트를 정했다: 표시용 `IBM Plex Sans KR`, 본문 `Pretendard Variable`,
수치용 `IBM Plex Mono`. 조달 계획은 (a) 표시용은 빌드타임 정적 서브셋 ≤25KB, (b) 본문은 다이나믹 서브셋 CDN,
(c) 수치용은 라틴 서브셋 ≤10KB였다.

구현 단계에서 이 계획이 두 제약과 충돌한다는 것이 드러났다.

1. **TRD S-3은 런타임 외부 리소스 로드를 금지한다.** 본문의 "다이나믹 서브셋 CDN"은 이 규칙 위반이다.
   자체 호스팅으로 바꾸면 한글 다이나믹 서브셋은 파일이 수백 개로 쪼개진다.
2. **TRD C-3은 오프라인 전 기능 동작을 요구하고, 서비스워커는 전량 프리캐시 전략이다**(ADR-0009).
   다이나믹 서브셋은 "필요한 조각만 받는" 것이 이점인데, 전량 프리캐시하면 그 이점이 사라지고
   한글 조각 전체(1MB 이상)를 첫 방문에 받게 된다. 두 설계가 정면으로 배타적이다.
3. 표시용 정적 서브셋(≤25KB)은 성립하지만, **서브셋 대상 문자 집합이 고정되어야 한다.**
   이 앱의 헤드라인에는 게임 아이템명이 들어가고(ADR-0017에 따라 750개 아이템명이 데이터에서 온다),
   게임 패치마다 문자 집합이 바뀐다. 빌드가 폰트 서브셋 생성에 의존하게 되고, 파이프라인이 하나 더 늘어난다.

## 결정

**한글을 포함하는 표시·본문 텍스트는 시스템 폰트 스택으로 조판한다. 수치용 `IBM Plex Mono`만 자체 호스팅한다.**

```
--font-display: 'Bahnschrift', 'DIN Alternate', 'Pretendard Variable', Pretendard, …
--font-body:    'Pretendard Variable', Pretendard, -apple-system, 'Segoe UI Variable Text', …
--font-mono:    'IBM Plex Mono', ui-monospace, Consolas, D2Coding, monospace
```

- `IBM Plex Mono` 라틴 서브셋 400/500 두 개만 `src/fonts/`에 두고 번들러가 해시·서빙한다 (합계 29.6KB).
  OFL 1.1 라이선스 원문을 `public/fonts/IBM-Plex-Mono-LICENSE.txt`로 함께 배포한다.
- 위계는 **두 번째 한글 서체가 아니라 굵기·크기·자간·모노 라벨**로 만든다. 브리프 §04의 스케일 표는 그대로 지킨다.
- Pretendard가 설치된 기기에서는 자동으로 쓰인다(스택 1순위). 없으면 OS 기본 한글 서체로 떨어진다.

## 근거

1. **수치가 이 앱의 콘텐츠다.** 분당 생산량, 기계 대수, 전력 MW, 벨트 처리량 — 화면의 정보 밀도 대부분이 숫자다.
   `tabular-nums`와 슬래시 제로가 주는 이득은 표의 자릿수 정렬에서 즉시 눈에 보인다.
   **한정된 폰트 예산을 쓸 곳이 있다면 여기다.**
2. **한글 웹폰트의 비용 대비 이득이 이 앱의 사용 맥락에서 낮다.** 게임 중 알트탭으로 3초 보고 돌아가는 도구다.
   조판 품질보다 즉시성이 우선이며, 오프라인 프리캐시 정책과도 충돌한다.
3. **브리프가 경계한 "AI 티 지문 1번"은 단일 폰트 자체가 아니라 위계 없음이다**(§07-1).
   모노 라벨 + 굵기·크기 대비 + 규칙선으로 위계를 만들면 그 지적은 회피된다.
4. 폰트 서브셋 파이프라인을 도입하지 않음으로써 빌드 의존성이 하나 줄어든다(TRD C-4).

## 결과

- **기기마다 한글 렌더링이 다르다.** Windows 기본 한글 서체의 조판 품질은 좋지 않다. 이것은 실제 손실이다.
- `Bahnschrift`는 Windows 전용이라 macOS/Linux에서는 `DIN Alternate` 또는 Pretendard로 떨어진다.
  즉 **표시용 서체가 플랫폼마다 다르다.** 압축된 산업체 느낌은 Windows에서 가장 강하게 나온다.
- 브리프 §04의 폰트 예산표(Display 25KB / Body 비차단 / Numeric 10KB)는 이 ADR로 대체된다.
  실제 차단 리소스는 **0KB**(모노는 `font-display: swap`으로 비차단, 29.6KB)다.
- CLS 방어용 `size-adjust` 측정 작업이 불필요해진다.

## 재검토 조건

다음 중 하나가 성립하면 이 결정을 다시 판단한다.

1. 서비스워커 전략이 전량 프리캐시에서 선택적 캐시로 바뀐다 → 다이나믹 서브셋이 다시 성립한다
2. 헤드라인 문자 집합을 데이터와 무관하게 고정할 수 있게 된다 → 정적 서브셋 ≤25KB가 성립한다
3. 실사용에서 한글 조판 품질이 문제로 보고된다

## 검토한 대안

| 대안 | 기각 사유 |
|---|---|
| **브리프 원안(Plex Sans KR 정적 서브셋 + Pretendard 다이나믹 CDN)** | CDN이 TRD S-3 위반. 자체 호스팅 시 전량 프리캐시와 충돌 |
| **Pretendard 전량 자체 호스팅(가변 woff2 통짜)** | 한글 완성형 11,172자. 첫 화면 차단 리소스가 수백 KB로 P-1(LCP 1.5s) 위협 |
| **폰트 없이 전부 시스템 스택** | 수치 정렬(`tabular-nums`)과 0/O 구분을 잃는다. 표가 핵심인 앱에서 손실이 크다 |
| **구글 폰트 링크** | TRD S-3 위반. 오프라인에서 폴백으로 떨어져 조판이 흔들린다 |
