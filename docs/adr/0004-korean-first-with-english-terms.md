# ADR-0004: 한국어 우선, 게임 용어는 영문 병기

- **상태**: 채택
- **날짜**: 2026-08-19

## 맥락
대상 사용자는 한국어 화자다. 그러나 Satisfactory의 원본 용어는 전부 영어이고, 사용자가 참조할 외부 도구(인터랙티브 맵, 계산기, 위키, 유튜브 공략)는 대부분 영어다.

한글 전용으로 쓰면 읽기는 편하지만 외부 도구와 대조할 때 용어를 다시 번역해야 한다. 영문 전용은 읽기 부담이 크다.

## 결정
- UI와 문서의 본문은 **한국어**
- 게임 용어(아이템·건물·레시피·바이옴·마일스톤)는 **한글(영문) 병기**
  - 예: `강화 철판(Reinforced Iron Plate)`, `피복 산업용 빔(Encased Industrial Beam)`
  - 첫 등장 시 병기, 같은 문단 내 반복은 한글만
- 데이터 스키마에 `nameKo`와 `nameEn`을 모두 둔다. 표시 방식은 UI가 결정한다
- UI 언어 전환(i18n)은 **하지 않는다**. 문서량이 2배가 되고 1인 유지보수에서 낡는다
- 코드 식별자·파일명·커밋 메시지는 영어

## 근거
- 사용자가 명시적으로 선택했다
- 병기는 외부 도구와의 대조 비용을 없앤다 — 이 앱이 SCIM 인터랙티브 맵으로 연결하는 구조이므로 특히 중요하다
- 전면 i18n은 유지보수 부담 대비 이득이 불확실하다. 필요해지면 그때 ADR로 재검토한다

## 결과
- 텍스트가 길어진다. 레이아웃에서 병기를 고려해야 한다 (줄바꿈, 표 너비)
- 영어 사용자는 이 앱을 쓰기 어렵다. 공개 제품이지만 1차 대상은 한국어 화자다
- 데이터에 이름 필드가 두 벌 필요하다

## 검토한 대안
- **한글 전용**: 외부 도구 대조가 불편하다
- **한/영 전환 지원**: 문서량 2배, 유지보수 부담. 필요성이 입증되면 재검토
