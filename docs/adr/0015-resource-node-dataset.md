# ADR-0015: 자원 노드 좌표는 MIT 라이선스 커뮤니티 데이터셋을 쓴다

- **상태**: 채택
- **날짜**: 2026-08-19 (사후 기록 — 데이터는 커밋 `7bc6263`에서 이미 도입되었다)
- **관련 결정**: ADR-0003(public 저장소·게임 자산), ADR-0006(맵 오버레이), ADR-0008(게임 데이터 소스)

## 맥락

"어느 노드를 쓸지"까지 계획하려면 노드의 월드 좌표와 순도가 필요한데, 게임이 배포하는
`CommunityResources/Docs`에는 **없다**(아이템·레시피·건물·스키매틱만 있고 맵 배치는 미포함).

이전 세션에서 `lukszi/SatisfactoryMCP`의 `world_resource_nodes.json`을 찾았으나
**라이선스가 NOASSERTION**이었다. 라이선스 미표기 저장소의 법적 기본값은 저작권자 전권이며,
이 저장소는 public + MIT다. 번들하면 ADR-0003에서 스스로 정한 원칙을 어긴다 → 채택 보류했다.

## 결정

**`rockfactory/satisfactory-logistics`(MIT)의 `WorldResourceNodes.json`을 변환해 사용한다.**

- 산출물: `src/data/resource-nodes.json` (626개 노드, 105KB)
- 각 노드: `{ id, res(클래스명), ko, purity, type, fx, fy, gx, gy, cell }`
- `fx`/`fy`는 맵 이미지 기준 0~1 비율 좌표 — ADR-0006의 캘리브레이션과 같은 좌표계
- 월드 좌표 환산식은 파일의 `$transform` 필드에 기록한다 (거리 계산에 필요)
- 출처와 라이선스를 파일 안(`$source`)과 화면 각주에 **둘 다** 표기한다

## 근거

1. **라이선스가 명시적으로 MIT다.** public 저장소에 번들할 근거가 있다 — 보류 사유가 해소되었다.
2. 게임 설치본의 `.pak` 언팩(대안 3)은 난이도가 높고, 그 산출물의 재배포 지위는 오히려 더 불명확하다.
3. 런타임 fetch(대안 4)는 TRD S-3(외부 리소스 런타임 로드 금지)과 C-3(오프라인) 위반이다.
4. 세이브 파일에서 추출(대안 5)하면 **이미 채굴기를 꽂은 노드만** 나온다. "아직 안 쓴 노드를 계획한다"는
   목적에 정면으로 안 맞는다.

## 결과

- 시작 부지별로 "티어 1에 필요한 노드가 어디 있고 몇 미터인가"를 계산할 수 있다 (`SiteMap` 아일랜드).
- **자원 랜덤화(1.2 옵션)를 켜면 이 데이터가 전부 무효다.** 화면에서 설정을 받아 경고한다 (FRD F2-10).
- 게임 패치로 노드 배치가 바뀌면 이 데이터셋의 갱신을 기다려야 한다. `build-data.mjs`처럼
  게임 원본에서 재생성할 수 없는 유일한 데이터다 — 드리프트 위험이 상대적으로 크다.
- 순도 3단계(불순/보통/순수)와 종류(node/deposit/간헐천)를 구분해 보관한다. 채굴기 산출 계산에
  순도 배율(×0.5 / ×1 / ×2)을 적용한다.

## 검토한 대안

| 대안 | 기각 사유 |
|---|---|
| **lukszi/SatisfactoryMCP** | 라이선스 NOASSERTION. 활발히 유지되지만 사용 권한이 없다 |
| **게임 `.pak` 직접 언팩** | 난이도 높고 재배포 지위 불명확 |
| **런타임 외부 fetch** | TRD S-3·C-3 위반 |
| **세이브 파일에서 추출** | 이미 사용 중인 노드만 나와 계획 용도에 부적합 |
| **노드 데이터 없이 진행** | "어느 노드를 쓸지"가 이 앱의 입지 선정 화면의 핵심이다. 없으면 화면이 성립하지 않는다 |
