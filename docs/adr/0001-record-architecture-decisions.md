# ADR-0001: 아키텍처 결정을 기록한다

- **상태**: 채택
- **날짜**: 2026-08-19

## 맥락
이 프로젝트는 1인이 장기간 유지보수한다. 몇 달 뒤의 나 자신이 "왜 이렇게 했지"를 묻게 된다. 되돌리기 어려운 결정일수록 근거가 사라지면 재논의 비용이 크다.

또한 이 저장소는 공개되며, 리서치 기반으로 만들어진다. 결정의 근거가 없으면 외부에서 신뢰할 수 없다.

## 결정
되돌리기 어렵거나 비용이 큰 결정은 ADR로 기록한다.

- 파일명: `NNNN-kebab-case-title.md`
- 형식: 제목 / 상태 / 날짜 / 맥락 / 결정 / 근거 / 결과 / 검토한 대안
- 언어: 한국어
- 상태: `제안` → `채택` → (`폐기` | `Superseded by ADR-NNNN`)

**기존 ADR은 수정하지 않는다.** 결정이 바뀌면 새 ADR을 쓰고 이전 것의 상태를 변경한다. 이력이 남아야 왜 바뀌었는지 알 수 있다.

## ADR을 쓰는 기준
쓴다: 기술 스택 선택, 데이터 저장 방식, 외부 의존성 도입, 저장소 구조, 라이선스, 공개 범위, 알고리즘 선택
쓰지 않는다: 변수명, 함수 분리, CSS 값, 문구 수정 — 되돌리기 쉬운 것

## 결과
- 결정마다 문서가 하나씩 늘어난다. 이는 비용이지만 재논의 비용보다 싸다
- 리서치 근거는 `docs/research/`에 따로 남기고 ADR에서 참조한다

## 검토한 대안
- **위키/노션에 기록**: 코드와 분리되면 낡는다. 저장소 안에 두어 함께 리뷰되게 한다
- **커밋 메시지로 대체**: 검색과 통람이 어렵다
