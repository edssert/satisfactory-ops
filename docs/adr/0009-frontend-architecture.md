# ADR-0009: 프론트엔드는 Astro 정적 출력 + Preact 아일랜드로 만든다

- **상태**: 채택
- **날짜**: 2026-08-19
- **관련 리서치**: `docs/research/arch-islands.md`, `arch-spa.md`, `arch-zero-build.md`, `arch-offline.md`
- **관련 결정**: ADR-0010(백엔드), ADR-0011(상태), ADR-0012(데이터), ADR-0013(솔버)

## 맥락

2026-08-19 세션에서 아키텍처 제안서 4건을 병렬로 작성했으나 **심사(비교·채점)를 마치지 못한 채 세션이 끝났다.**
그 상태에서 화면 구현이 먼저 진행되어, 스택이 미확정인 채로 `index.html`(25KB)과 `start.html`(75KB)
두 개의 손수 작성한 단일 HTML 파일이 만들어졌다. `docs/DESIGN-BRIEF.md`도 함께 건너뛰어졌다.

이 ADR은 그 중단된 심사를 완주한 결과다.

### 채점 (가중 합계 / 만점 80)

| 기준 (가중) | 무빌드 바닐라 | Astro+아일랜드 | Vite+Svelte SPA |
|---|---|---|---|
| 5년 유지보수·방치 후 복귀 (×3) | 5 | 2 | 3 |
| 요구 적합성 — 상태 파생·맵·계산기·세이브 (×3) | 3 | 4 | 5 |
| 데이터 정합성 — 872개 레시피가 화면 수치와 어긋나지 않는가 (×3) | 3 | 5 | 4 |
| 성능·오프라인 (×2) | 5 | 5 | 4 |
| 공개 발견가능성·랜딩 (×2) | 2 | 5 | 1 |
| 장애 반경 (×2) | 2 | 5 | 2 |
| 착수·기존 화면 이식 비용 (×1) | 5 | 2 | 2 |
| **합계** | **56** | **65** | **52** |

`arch-offline.md`는 독립 후보에서 제외했다. 제안서 스스로 §0에 "프레임워크는 이 목표를 방해하지 않는 것 중
아무거나 고르면 된다"고 적었다. 이것은 아키텍처가 아니라 **서비스워커 설계 지침**이며, 어느 안을 골라도
§4(오프라인 정합성)·§5(업데이트 전략)·§6(GitHub Pages 함정)을 그대로 채택한다.

### 판정을 가른 것 — 이 저장소의 실제 버그 이력

제안서의 추상적 장단점보다 이 저장소가 이미 겪은 사고가 더 강한 증거였다.

| 커밋 | 사고 | 어느 안이 구조적으로 막는가 |
|---|---|---|
| `de36c39` | TDZ 오류 하나로 시작 가이드 **화면 전체가 백지** | Astro — 페이지가 정적 HTML이라 아일랜드만 죽는다 |
| `bd981f4` | HTML에 손으로 적은 벨트 처리량이 데이터와 어긋남 (4건) | 빌드타임 렌더 + 스키마 검증 → 빌드가 죽는다 |
| `2b5cdad` | 같은 제작기 대수를 구성도와 표에 두 번 타이핑해 불일치 | 같음 |
| `5260767` | 마크업과 스크립트가 따로 놀아 클릭 핸들러 누락 | 컴포넌트 경계 + TypeScript |

즉 현재의 문제는 "디자인 지시서를 안 따랐다"가 아니라 **수치가 데이터가 아니라 사람 손에서 온다**는 구조 문제다.
이것을 막는 게이트가 있는 안이 이겨야 한다.

## 결정

**Astro 7 + Preact 10 아일랜드 + TypeScript, `output: 'static'`, GitHub Actions로 Pages 배포.**

1. **문서 화면은 JS 0KB 정적 HTML** — 랜딩, 용어집, 레퍼런스 표, 성장 단계도.
   모든 수치는 `src/data/`에서 **빌드타임에** 렌더한다. 마크업에 숫자를 타이핑하지 않는다.
2. **도구 화면만 아일랜드** — 마일스톤 체크리스트, 맵 팬/줌, 생산 계산기.
   규칙: **"상태를 소유하는 최소 단위만 아일랜드"**. 페이지 전체를 아일랜드로 만들면 이 선택의 이점이 증발한다.
3. **UI 프레임워크·CSS 프레임워크 없음** — 순수 CSS + 커스텀 프로퍼티. 토큰은 `docs/DESIGN-BRIEF.md`를 정본으로 한다.
4. **서비스워커는 `arch-offline.md` §4~6을 그대로 채택** — 전량 프리캐시, `prompt` 업데이트, 원자적 install.
5. **데이터 상호참조는 Zod로 검증**하고, 깨지면 **빌드를 실패시킨다**. 런타임에 링크가 죽게 두지 않는다.
6. **실험적 API 금지.** `client:*` 디렉티브와 Content Layer 등 안정 API만 쓴다. 마이너 버전을 고정한다.

검증한 버전(npm 레지스트리 실측, 2026-08-19): `astro 7.2.3`, `preact 10.29.8`, `vite 8.2.1`.

## 근거

1. **이 앱의 실패 모드는 상태 관리가 아니라 데이터 드리프트다.** 위 버그 표가 그것을 보여준다.
   Astro는 872개 레시피를 빌드타임에 HTML로 굳히므로, 수치를 손으로 옮길 자리 자체가 없어진다.
2. **이 앱은 문서 80% + 도구 20%다.** 용어집 한 항목을 읽으려고 계산기와 맵 코드를 내려받는 것은
   알트탭 도구에서 낭비다. 문서 페이지 JS 0KB는 성능 예산(TRD P-1~P-3)을 여유롭게 만든다.
3. **공개 제품이다.** PRD가 정한 대상은 개인 추적 + 공개 플레이북이다. 해시 라우팅 SPA는 검색 유입이 0에
   가깝다. 랜딩페이지를 만들라는 요구도 정적 HTML을 가리킨다.
4. **장애 반경이 작다.** SPA는 JS 하나가 터지면 백지가 된다 — 이 저장소는 이미 `de36c39`에서 겪었다.
   정적 페이지는 아일랜드가 죽어도 본문이 읽힌다.
5. **탈출 비용이 유한하다.** 산출물이 순수 정적 HTML이므로, Astro가 사라져도 `dist/`를 소스 삼아 살릴 수 있다.
   런타임 프레임워크에 묶인 SPA에는 없는 보험이다.

## 결과

### 좋아지는 것
- 화면의 모든 수치가 `src/data/`에서 온다. 게임 패치 → `build-data.mjs` 재실행 → 화면이 자동으로 갱신된다.
- 데이터 참조가 깨지면 배포가 아니라 **빌드**가 죽는다.
- 문서 페이지는 JS 없이 읽히고 검색에 잡힌다.

### 나빠지는 것 / 감수하는 것
- **Astro 메이저 회전율.** 18개월에 5→6→7. 연 1회 마이그레이션 세금을 각오한다.
  → 완화: 실험적 API 금지, 마이너 고정, `.nvmrc`로 Node 고정, lockfile 커밋.
- **`npm run dev`가 필요해진다.** "파일 고치고 새로고침"의 마찰이 생긴다.
- **의존성 표면이 400~600 패키지로 늘어난다.** public 저장소이므로 Dependabot 알림이 온다.
- **GitHub Pages 배포 방식이 바뀐다.** 현재 legacy(main 브랜치 루트 서빙) → Actions 워크플로.
  전환 시점에 짧은 배포 공백이 있다.
- **기존 `index.html` / `start.html`을 이식해야 한다.** 손으로 적힌 수치는 이식 과정에서 전부
  데이터 유래 계산으로 바꾼다 (그것이 이 결정의 목적이다).

## 검토한 대안

| 대안 | 기각 사유 |
|---|---|
| **무빌드 바닐라 ES 모듈** (56점) | 유지보수 최강이지만 데이터 정합성 게이트와 타입 안전망이 없다. 이 저장소가 실제로 겪은 4건의 버그를 구조적으로 막지 못한다. 결국 "JSON을 HTML로 바꾸는 자작 SSG"를 짜게 되며, 그것은 검증된 빌드보다 나쁘다 |
| **Vite + Svelte 5 SPA** (52점) | 상태 파생 표현력은 최고지만 SEO가 사실상 0이고, JS 실패 시 백지가 되는 실패 모드를 유지한다. 랜딩페이지 요구와 정면으로 어긋난다 |
| **오프라인 우선 PWA** | 아키텍처가 아니라 SW 설계 지침. 독립 후보에서 제외하고 §4~6을 채택안에 흡수했다 |
| **11ty** | 더 가볍고 메이저 변동이 적다. 그러나 아일랜드 프리미티브가 없어 계산기·맵의 하이드레이션 경계를 손으로 짜야 하고, 그 코드가 곧 부채가 된다 |
| **현행 단일 HTML 유지** | 요구("제대로된 프론트엔드")를 충족하지 못하고, 위 버그 4건의 원인을 그대로 남긴다 |
