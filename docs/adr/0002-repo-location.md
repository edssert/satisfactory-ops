# ADR-0002: 저장소를 OneDrive 밖(`C:\Dev`)에 둔다

- **상태**: 채택
- **날짜**: 2026-08-19

## 맥락
사용자의 작업 폴더는 `C:\Users\User\OneDrive\00.Workspace\`이고, 처음에 `GAME\Satisfactory\` 하위에 프로젝트 폴더를 만들었다.

그러나 워크스페이스 규칙(`00.Workspace\CLAUDE.md`)에 다음이 명시되어 있다:

> 코드 저장소(.git)를 이 폴더에 두지 않는다 → `C:\Dev`

이는 취향이 아니라 실제 손상 방지책이다. OneDrive는 `.git` 내부 파일(객체, 인덱스, 락 파일)을 다른 파일과 똑같이 동기화한다. 그 결과:
- `index.lock`이 동기화되어 git 작업이 교착
- 객체 파일이 부분 동기화되어 저장소 손상
- 브랜치 전환 시 대량 파일 변경이 동기화 큐를 막음

## 결정
저장소는 `C:\Dev\satisfactory-ops`에 둔다. OneDrive 하위의 `GAME\Satisfactory\` 폴더에는 저장소를 가리키는 포인터 문서만 남긴다.

## 근거
- 워크스페이스 규칙에 이미 명시된 사항이다
- OneDrive + `.git` 손상은 널리 알려진 실제 문제다
- 백업은 GitHub 원격이 담당한다. OneDrive의 이중 백업은 불필요하고 위험하다

## 결과
- 파일 탐색기에서 프로젝트가 두 곳에 나뉜다 (문서 포인터 / 실제 코드)
- OneDrive 자동 백업 대상이 아니므로 **원격 푸시가 유일한 백업**이다. 작업 후 푸시를 미루지 않는다

## 검토한 대안
- **OneDrive에 두고 `.git`을 동기화 제외**: OneDrive의 선택적 동기화는 폴더 단위이며 숨김 폴더 제외가 안정적이지 않다
- **OneDrive에 두고 감수**: 손상 시 복구 비용이 크다
