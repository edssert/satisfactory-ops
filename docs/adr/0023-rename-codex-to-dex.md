# ADR-0023: `/codex/` 를 `/dex/` 로 옮기고 「도감」으로 부른다

- **상태**: 채택
- **날짜**: 2026-08-21

## 맥락

게임 안의 모든 해금과 수치를 모아 둔 참고 화면 묶음(티어·MAM·상점·대체 제작법·레퍼런스 표)을
`/codex/` 아래에 두고 「Codex」라고 불렀다. 게임 자체가 자기 정보 화면을 codex라고 부르는 관례가
있어서 자연스러워 보였다.

문제는 **다른 회사 제품이 그 이름을 쓴다**는 것이다. 「Codex」는 지금 OpenAI의 코딩 제품 이름으로
널리 통한다. 이 앱의 방문자는 대체로 개발 도구를 아는 사람들이고, 상단 내비게이션의 「Codex」는
게임 도감이 아니라 그 제품을 연상시킨다.

`CLAUDE.md`의 "하지 않는 것"에 **"게임사 브랜딩을 사칭하지 않는다"**가 있다. 여기서 걸리는 것은
게임사가 아니라 제3자지만, 이름이 남의 제품을 가리키게 두는 것은 같은 성격의 문제다.
게다가 이 앱의 본문은 한국어인데 그 화면만 영어 라틴어 이름이었다.

## 결정

**주소를 `/codex/` → `/dex/` 로 옮기고, 화면 이름을 「도감」으로 바꾼다.**

- 내비게이션 라벨: 「도감」 (`src/layouts/Base.astro`)
- 새 주소: `/dex/`, `/dex/tiers/[tier]/`, `/dex/mam/[tree]/`, `/dex/shop/[tab]/`,
  `/dex/recipes/`, `/dex/reference/`
- **옛 주소 34개를 전부 남긴다.** `src/pages/codex/` 아래에 같은 라우트 구조로 리다이렉트 페이지를
  두고, 동적 라우트는 `getStaticPaths()`로 같은 개수를 생성한다:
  루트 1 + `tiers` 1+10 + `mam` 1+9 + `shop` 1+9 + `recipes` 1 + `reference` 1 = **34개**
- 리다이렉트 수단은 **`<meta http-equiv="refresh" content="0; url=…">` + `<link rel="canonical">`**,
  그리고 자동 이동이 막혔을 때를 위한 눈에 보이는 링크 한 줄.
- `/tech/`, `/recipes/`, `/tools/` 도 같은 방식으로 남겼다 — 도감으로 합치기 전의 옛 주소다.

## 근거

- **이름은 제품이 무엇인지 말하는 첫 번째 수단이다.** 남의 제품을 가리키는 이름은 그 일을 못 한다.
- **「도감」은 이 화면이 실제로 하는 일이다.** 진행도와 무관하게 게임 안의 모든 것을 나열한다.
  가이드(진행형)와 성격이 갈리는 지점이 이름에서 드러난다.
- **`/dex/`는 짧고 「도감」과 뜻이 붙는다.** `pokedex`류의 관용이 이미 있어 낯설지 않다.
- 리다이렉트를 `_redirects`나 서버 규칙이 아니라 **페이지로** 남긴 이유:
  GitHub Pages 정적 배포에는 리다이렉트 규칙을 쓸 서버가 없다(ADR-0010).
  meta-refresh는 서버 없이 동작하고, `rel="canonical"`이 검색 엔진에 새 주소를 알린다.

## 결과

- **되돌리기 어렵다.** 외부에 이미 `/codex/…` 링크가 나가 있을 수 있고(공개 저장소·배포 사이트),
  한 번 나간 링크는 회수할 수 없다. 그래서 리다이렉트는 **지우지 않는다.**
  옛 주소를 삭제하는 것은 별도의 결정이며 새 ADR을 요구한다.
- meta-refresh는 HTTP 301이 아니다. 검색 엔진이 즉시 새 주소로 옮겨 주지 않고,
  브라우저 뒤로 가기에서 되돌아 튀는 일이 있다. 정적 배포에서 쓸 수 있는 최선이다.
- 옛 주소 페이지 34개가 빌드 산출물에 계속 남는다. 각각 300바이트 남짓이라 비용은 무시할 만하다.
- **리다이렉트 페이지의 골격이 두 갈래다.** `/tech/`·`/recipes/`·`/tools/` 는 `<html lang="ko">` 와
  배경색을 직접 적어 넘어가기 전 흰 화면 번쩍임을 막는데, `/codex/` 34개는 `<meta>` 만 있고
  문서 골격이 없다. 같은 처리를 해 두는 편이 낫다 — 남은 부채로 기록한다.

## 검토한 대안

- **이름만 바꾸고 주소는 `/codex/`로 둔다**: 주소가 UI에 노출된다(주소창·공유 링크).
  이름과 주소가 갈리면 둘 다 기억해야 한다. 탈락.
- **`/reference/` 나 `/library/`**: 뜻은 맞지만 길고, 「도감」과 한 낱말로 붙지 않는다.
- **`/wiki/`**: 이 화면은 위키가 아니다. 편집할 수 없고, 실제 위키(satisfactory.wiki.gg)와
  혼동된다 — 그쪽이 우리 데이터의 출처 중 하나라 더 나쁘다. 탈락.
- **리다이렉트 없이 그냥 옮긴다**: 외부 링크가 전부 404가 된다. 공개 저장소이므로 링크가
  이미 나갔을 가능성을 배제할 수 없다. 탈락.
- **JavaScript로 `location.replace()`**: JS가 꺼져 있으면 동작하지 않는다.
  이 저장소는 문서 화면에 JS 0KB를 기본값으로 삼는다(ADR-0009). 탈락.
