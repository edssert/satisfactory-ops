# ADR-0007: PRD / FRD / TRD / ADR 4종 문서 체계를 쓴다

- **상태**: 채택
- **날짜**: 2026-08-19

## 맥락
이 프로젝트는 리서치 기반으로 만들어지며, 결정의 근거가 산출물의 신뢰를 결정한다. 또한 여러 병렬 에이전트가 문서를 생산하므로 어디에 무엇을 쓸지 경계가 없으면 중복과 모순이 생긴다.

## 결정
| 문서 | 답하는 질문 | 변경 빈도 |
|---|---|---|
| `PRD.md` | 무엇을 왜 만드는가. 누구를 위한 것인가 | 낮음 — 방향 전환 시 |
| `FRD.md` | 각 기능이 구체적으로 어떻게 동작하는가 | 중간 — 기능 추가·변경 시 |
| `TRD.md` | 어떤 기술 제약과 품질 기준을 만족해야 하는가 | 중간 |
| `adr/*.md` | 이 결정을 왜 이렇게 내렸는가 | 추가만 — 수정 금지 |

보조 문서:
- `ARCHITECTURE.md` — 결정된 구조의 전체 그림
- `DATA-MODEL.md` — 데이터 논리 모델
- `DESIGN-BRIEF.md` — 시각 설계 지시서
- `research/*.md` — 조사 근거 원본. **결론이 아니라 근거를 담는다**

경계 규칙:
- PRD는 **기능을 명세하지 않는다**. 문제와 성공 기준만
- FRD는 **기술을 명세하지 않는다**. 동작만
- TRD는 **왜 그 기술인지 설명하지 않는다**. 그건 ADR
- ADR은 **현재 상태를 서술하지 않는다**. 결정 시점의 맥락과 근거만

## 근거
- 각 문서가 하나의 질문에 답하면 갱신할 곳이 명확하다
- 병렬 에이전트에게 "어느 파일에 쓰라"를 지시할 수 있다
- 공개 저장소에서 외부인이 프로젝트를 이해하는 경로가 된다

## 결과
- 문서 유지 비용이 생긴다. 코드 변경 시 어느 문서가 낡았는지 확인해야 한다
- `CLAUDE.md`에 절차를 명시해 이 확인을 강제한다

## 검토한 대안
- **README 하나로 통합**: 규모가 커지면 찾을 수 없다
- **ADR만 쓰기**: 결정의 이유는 남지만 현재 요구사항의 전체 그림이 없다
