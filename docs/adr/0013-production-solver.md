# ADR-0013: 생산 체인은 DAG 재귀 + 유리수로 풀고, 순환은 v1에서 거부한다

- **상태**: 채택
- **날짜**: 2026-08-19
- **관련 리서치**: `docs/research/data-modeling.md`, `arch-islands.md` §4-4
- **관련 결정**: ADR-0009, ADR-0012

## 맥락
생산 계산기(FRD F5)는 "강화 철판 20/분"에서 시작해 원광까지 거슬러 올라가 기계 대수·전력·원자재 소비를 낸다.
문제는 두 가지다. (a) 부동소수점 누적 오차, (b) **순환 레시피** — `Recycled Plastic ↔ Recycled Rubber`,
`Packaged Fuel ↔ Unpackage Fuel`처럼 서로를 재료로 쓰는 쌍은 재귀로 풀리지 않는다.

## 결정

1. **비순환 구간은 재귀 순회로 푼다.** 목표 아이템에서 시작해 레시피 트리를 내려가며 필요 비율을 누적한다.
2. **모든 비율 계산은 유리수(분자/분모)로 한다.** 부동소수점은 표시 직전에만 쓴다.
   기계 대수는 `Math.ceil(x - 1e-9)` (CLAUDE.md 규약).
3. **순환은 SCC(강결합요소)로 탐지하고, v1에서는 계산을 거부한다.**
   화면에 이렇게 표시한다: *"이 체인은 순환 레시피를 포함해 정확한 해를 계산할 수 없습니다.
   해당 대체 레시피를 끄면 계산됩니다."*
4. **LP 솔버는 v1.1로 미루고, 도입 시 동적 임포트로 격리한다.** 티어 1~4만 쓰는 대부분의 사용자는
   솔버 코드를 내려받지 않는다. `glpk.js`(WASM ~1MB)는 TRD P-3 때문에 후보에서 제외한다.
5. **솔버는 DOM을 모르는 순수 모듈**(`src/lib/solver.ts`)이다. 빌드타임(사전계산)과 브라우저에서 같은 코드를 쓴다.
6. **골든 테스트를 먼저 쓴다.** 위키 공표값과 대조 가능한 체인(강화 철판, 모듈식 골조, 로터)을 고정 케이스로 둔다.

## 근거
1. **틀린 숫자보다 거절이 낫다.** 이 앱의 제품 가치는 신뢰다. 순환 구간에서 그럴듯하지만 틀린 수치를 내면
   사용자는 그 공장을 실제로 짓는다. 계산기가 "가끔 틀린다"는 평판은 회복되지 않는다.
2. 순환 레시피는 전부 **대체 레시피**다. 즉 사용자가 켜야만 등장하며, 끄면 정확한 해가 나온다. v1에서 거부해도
   기본 경로는 100% 계산된다.
3. 유리수 산술은 50줄이면 되고, `2/3` 같은 비율이 누적될 때 "제련기 23.999대" 같은 표시를 원천 차단한다.
4. LP는 옳은 해법이지만 **버그 밀도 1위 구역**이다(제안서 4건 중 3건이 이것을 최대 리스크로 지목).
   v1 일정에서 잘라낼 수 있게 설계해두는 것이 1인 개발의 일정 관리다.

## 결과
- v1 계산기는 순환 대체 레시피 조합에서 결과를 내지 않는다. 이것은 기능 결손이며, UI에서 이유와 해결책을 명시한다.
- 유리수 산술을 직접 구현·테스트해야 한다 (약 50~80줄 + 테스트).
- LP를 나중에 넣을 때 인터페이스가 바뀌지 않도록, 솔버 진입점은 처음부터 `solve(target) → Result | Unsolvable`로 둔다.

## 검토한 대안
- **부동소수점 재귀만**: 누적 오차로 기계 대수가 경계에서 틀린다. 엡실론으로 덮으면 언제 덮이는지 알 수 없다
- **처음부터 LP**: 순환까지 정확히 풀지만 v1 일정을 통째로 잡아먹고, 수치적으로 특이한 행렬에서 조용히 틀린다
- **깊이 제한 재귀**: 순환을 "깊이 초과"로 얼버무린다. 잘못된 결과를 낼 수 있어 1번 원칙과 충돌한다
