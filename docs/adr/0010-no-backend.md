# ADR-0010: 백엔드를 두지 않는다

- **상태**: 채택
- **날짜**: 2026-08-19
- **관련 리서치**: `docs/research/arch-scope-backend.md`
- **관련 결정**: ADR-0009, ADR-0011

## 맥락
TRD C-1(서버 없음)은 이미 제약으로 확정되어 있었으나, "그래서 동기화·공유·텔레메트리는 어떻게 하는가"에
대한 답이 문서화되지 않았다. 이 ADR이 그 공백을 메운다.

## 결정
**서버·데이터베이스·인증을 두지 않는다.** 전부 정적 호스팅(GitHub Pages)으로 해결한다.

- 게임 데이터: 빌드 산출물로 앱과 함께 배포 (읽기 전용)
- 사용자 데이터: 브라우저 로컬에만 저장 (ADR-0011)
- 기기 간 이동: **JSON 내보내기/가져오기**. 자동 동기화는 하지 않는다
- 계획 공유: URL 해시에 상태를 인코딩해 링크로 공유 (서버 왕복 0)
- 텔레메트리: **없음** (TRD S-2)

## 근거
1. 이 앱의 데이터는 (a) 게임 패치 때만 바뀌는 정적 데이터와 (b) 한 사람의 로컬 진척뿐이다. 서버가 관여할 이유가 없다.
2. 계정·인증·DB를 두는 순간 유지보수 비용이 앱 본체를 넘는다. 1인 프로젝트에서 이것이 프로젝트를 죽이는 실제 원인이다.
3. 세이브 파일을 서버로 보내지 않는다는 프라이버시 약속(TRD S-1, C-2)이 구조적으로 보장된다 — 보낼 곳이 없다.
4. 운영 비용이 0이고, 5년 뒤에도 살아 있을 확률이 가장 높다.

## 결과
- **다기기 동기화가 없다.** PC의 진척이 태블릿에 자동으로 가지 않는다. 이것은 이 결정의 정면 약점이다.
- **어떤 화면이 쓰이는지 영원히 모른다.** 개선 방향이 직감과 소수 피드백에 의존한다.
- 백엔드가 정당화되는 유일한 시나리오는 다수 사용자의 공장 설계 공유·랭킹이며, v1 범위 밖이다.

## 검토한 대안
- **Gist/Drive 연동 동기화**: 인증을 끌고 들어와 "백엔드 없음"의 전제를 깬다. 토큰 관리 책임도 생긴다
- **서버리스 함수 몇 개만**: "몇 개만"이 유지되지 않는다. 배포 파이프라인과 비밀 관리가 통째로 따라온다
- **분석 도구 삽입**: TRD S-2 위반. 오프라인 우선 앱에서 정확하지도 않다
