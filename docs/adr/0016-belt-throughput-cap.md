# ADR-0016 — 벨트 처리량 상한을 설계도의 1급 제약으로 둔다

| | |
|---|---|
| 상태 | 채택 |
| 일자 | 2026-08-19 |
| 맥락 | 사용자가 "왜 구리·석회는 순도 높음이 아니고 일반이냐"고 물으면서 드러남 |

## 배경

티어 1 자동화 구성도에서 채굴기 산출(순수 노드 120/분)을 **벨트 한 줄**로 그렸다.
사용자 질문을 계기로 검증한 결과, 이는 게임에서 불가능한 배치였다.

## 근거 데이터 (verified)

출처: `CommunityResources/Docs/en-US.json` (UTF-16, steamBuildId 24656030).
`mSpeed ÷ 2 = 개/분`.

| 벨트 | mSpeed | 개/분 |
|---|---|---|
| Mk.1 | 120 | **60** |
| Mk.2 | 240 | 120 |
| Mk.3 | 540 | 270 |
| Mk.4 | 960 | 480 |
| Mk.5 | 1560 | 780 |
| Mk.6 | 2400 | 1200 |

**Mk.2는 티어 2(물류 Mk.2)에서 해금**된다. 즉 티어 1의 모든 벨트는 60/분이 상한이다.

## 결정

1. **모든 구성도에서 벨트 구간의 처리량이 해당 티어 벨트 상한을 넘지 않는지 검증한다.**
   넘으면 병렬 벨트로 그리거나 라인을 분할한다. "×N" 축약과 마찬가지로, 실제로 지을 수 없는 그림은 그리지 않는다.
2. 순도(purity)는 **채굴기 산출**을 정하고, 벨트는 **반출 가능량**을 정한다. 둘은 별개의 상한이며 둘 다 표시한다.
3. 노드 추천은 여전히 **순수 우선**이다. 지금 다 못 써도 벨트 업그레이드만으로 그대로 두 배가 되기 때문이다.

## 이 결정으로 고친 것 (start.html #t1auto)

| 구간 | 이전 | 이후 |
|---|---|---|
| 철광 (채굴기 → 제련기) | 1줄 120/분 ❌ | 채굴기 직후 스플리터 → **벨트 2줄 × 60** |
| 철잉곳 (제련기 → 제작기) | 1줄 120/분 ❌ | 매니폴드 2개 — A(제련기 1·2)→철판, B(제련기 3·4)→철봉, 각 60 |
| 전선 출력 | 1줄 120/분 ❌ | 2줄 표기 |
| 나사 출력 | 1줄 80/분 ❌ | 2줄 표기 |

## 남은 작업

- `src/data/buildings.json`에 `mSpeed`가 추출되지 않고 있다. `scripts/build-data.mjs`에 벨트·파이프 처리량 필드를 추가해 앱이 이 검증을 자동으로 하도록 한다.
- 검증을 CI 데이터 무결성 검사(TRD §8.1)에 넣는다.
