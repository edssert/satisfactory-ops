# ADR-0020: 대체 제작법 등급을 우리가 직접 계산한다

- 상태: Accepted
- 날짜: 2026-08-20

## 맥락

대체 제작법 우선순위를 처음에는 커뮤니티 분석글 하나에서 옮겨 적었다. 두 가지가 문제였다.

1. **단일 출처였다.** `CLAUDE.md` 규칙 4는 단일 출처 주장을 `disputed` 로 표시하고 앱 핵심
   데이터로 쓰지 말라고 한다. 그런데 그 순위를 화면의 정본으로 썼다.
2. **웹 검색 상위의 "티어 리스트" 사이트들은 독립 출처가 아니었다.** 점수가 소수점까지
   원문과 같다. 한 사람의 분석을 SEO 사이트들이 옮긴 것이다. 여러 곳에서 보인다고
   합의가 아니다.

독립 출처를 하나 더 찾으니(스팀 커뮤니티 가이드) 결과가 크게 달랐다 —
104건 중 두 등급 이상 벌어진 것이 46건이다. 그리고 **두 출처 모두 1.2 기준이 아니다.**

## 결정

**1.2 게임 데이터로 직접 계산해 등급을 매긴다.** 외부 순위는 대조용으로만 쓴다.

계산 방법(`scripts/rank-alternates.mjs`):

- **끝점**은 우주 엘리베이터 페이즈 1~5 전량이다. 초반만 보고 고른 제작법이 후반에
  발목을 잡는 일이 흔하므로 끝까지 본다. 페이즈 요구량은 게임 배포 데이터에 없어
  공식 위키에서 옮겼다(그 사실을 화면에 밝힌다).
- 기본 제작법만으로 한 번 풀어 기준선을 잡고, 대체 제작법을 하나씩 끼워 다시 푼다.
- **원자재는 실제 맵의 노드 수로 가중한다.** 순도별 개수가 데이터에 있으므로 맵 전체
  가용량을 추정할 수 있다. 우라늄 6개와 철 70여 개를 같은 무게로 셈하지 않는다.
- 점수 = 자원 절감 ×3 + 기계 절감 ×2 + 전력 절감 ×1. 자원을 가장 무겁게 두는 이유는
  맵의 노드가 유한하고 늘릴 수 없기 때문이다. **이 가중치는 판단이며 바꾸면 순위도 바뀐다.**
- 등급은 점수 분포의 분위수로 자른다. 임의의 절대값 경계를 쓰지 않는다.

화면에는 **우리 등급 하나만** 표시하고 그 순서로 정렬한다. 세 등급을 나란히 놓으면
고르는 사람이 판단을 떠안는다. 외부 평가는 카드 각주로 내리고, 크게 갈리는 항목에만
"평가 갈림"을 표시한다.

## 결과

- 좋은 점: 지금 버전 기준이다. 맵 희소도를 반영한다. 계산 과정이 저장소에 있어 재현·반박이 된다.
- 나쁜 점: 대체 제작법을 하나씩만 끼워 봐서 상호작용을 못 잡는다. 참조한 LP 모형은 이걸 한다.
  부산물 되먹임 최적화도 하지 않는다. 가중치가 바뀌면 순위가 바뀐다.
- 감수: 완벽한 최적화보다 **재현 가능하고 버전이 맞는 것**을 택한다. 한계는 화면에 적는다.
