## F1. 마일스톤 진행 체크리스트

### 목적
사용자가 현재 어디까지 왔는지 앱이 알고, 그에 맞춰 "지금 할 일"을 제시한다. **이 앱의 중심 기능이다.**

### 요구
| ID | 요구 | 수준 |
|---|---|---|
| F1-1 | T0~T9의 모든 마일스톤을 티어별로 표시한다 | MUST |
| F1-2 | 각 마일스톤에 해금 요구 부품과 수량을 표시한다 | MUST |
| F1-3 | 마일스톤을 완료로 체크할 수 있고, 체크 상태가 영속된다 | MUST |
| F1-4 | 체크 상태에 따라 **"현재 티어"를 자동 판정**하고 상단에 고정 표시한다 | MUST |
| F1-5 | 현재 티어에서 **다음에 할 일 3가지**를 우선순위와 함께 제시한다 | MUST |
| F1-6 | 각 마일스톤에 "이 시점 액션"과 "확장성 함정"을 표시한다 | MUST |
| F1-7 | 미래 티어의 내용을 미리 볼 수 있다 (스포일러 토글) | SHOULD |
| F1-8 | 완료율을 티어별/전체로 표시한다 | SHOULD |
| F1-9 | 마일스톤에서 관련 용어집 항목·단계도·계산기로 이동할 수 있다 | MUST |

### 예외·경계
- 체크 상태가 없는 최초 방문 → T0부터 시작하는 것으로 간주하고 온보딩 표시
- 사용자가 상위 티어를 체크했는데 하위가 비어 있음 → 경고하지 않는다 (건너뛰기 허용). 단 "현재 티어" 판정은 **체크된 것 중 최고 티어**를 쓴다

## F13. 공장 설계 도면 생성 (Layout Designer)

### 목적

**"무엇을 지을지"에서 끝내지 않고 "어떻게 배치해서 어떻게 연결할지"까지 도면으로 준다.**

기존 도구는 두 갈래다. 생산 계산기는 기계 대수까지만 알려주고, 배치 도구는 사용자가 직접 그리는
빈 캔버스를 준다(`docs/research/layout-design-tools.md` §2). 그 사이 — **목표를 넣으면 지을 수 있는
도면이 나오는 것** — 이 비어 있고, 이 앱은 사용자의 티어·해금 상태를 이미 알고 있으므로 그 자리를 채운다.

### 핵심 원칙

1. **도면의 모든 치수는 게임 데이터에서 온다.** 건물 크기는 `mClearanceData`의 충돌 박스 합집합이다
   (연구 문서 §4). 사람이 적은 치수를 도면에 쓰지 않는다.
2. **해금 상태를 반영한다.** 블루프린트 디자이너는 티어 4, 벨트 Mk.2는 티어 2다. 아직 없는 것을
   전제한 도면은 지을 수 없는 도면이다.
3. **지을 수 없는 도면을 내지 않는다.** 경계를 벗어나거나, 양정을 넘거나, 벨트 상한을 넘으면
   그럴듯한 그림 대신 **명시적으로 거부하거나 경고한다** (ADR-0013의 원칙과 같다).
4. **"영원히 안 뜯는 설계"를 약속하지 않는다.** 커뮤니티 근거상 후반 재건축은 정상이다(연구 문서 §7).
   목표는 **뜯을 때 싸게 뜯는 설계**다.

### F13-A. 배치 생성

| ID | 요구 | 수준 |
|---|---|---|
| F13-1 | 생산 목표(아이템·분당 수량)에서 계산기 결과를 받아 기계 종류·대수를 확정한다 | MUST |
| F13-2 | 8m 파운데이션 격자 위에 기계를 배치한다. 건물 치수는 게임 데이터의 충돌 박스를 쓴다 | MUST |
| F13-3 | 매니폴드를 기본 분배 방식으로 쓰고, 분배기·병합기 위치를 배치에 포함한다 | MUST |
| F13-4 | 각 라인의 입력·출력 지점과 유량(개/분)을 도면에 표기한다 | MUST |
| F13-5 | 벨트 처리량 상한을 검사하고, 초과하면 필요한 벨트 등급 또는 라인 수를 제시한다 | MUST |
| F13-6 | 확장 방향(추가 기계를 붙일 자리)을 도면에 표시한다 | SHOULD |

### F13-G. 클럭·소머슬룹 최적화

기계 대수는 클럭과 소머슬룹에 따라 달라지므로, 이것은 배치의 **입력값**이다.
아래 수치는 게임 데이터와 공식 위키에서 확인했다.

| 값 | 확인값 | 출처 |
|---|---|---|
| 클럭 범위 | 1% ~ 250% | 위키 Clock speed |
| 파워 샤드 | 1개당 최대 클럭 +50%, 최대 3개 | 게임 데이터 `mExtraPotential = 0.5` |
| 전력 지수 | **1.321929** | 게임 데이터 `mPowerConsumptionExponent` (위키 1.321928과 일치) |
| 소머슬룹 슬롯 | 제련소·제작기 1 / 조립기·주조소·정제소·변환기 2 / 제조기·혼합기·입자가속기·양자 인코더 4 | 위키 Production amplifier + 데이터 `somersloopSlots` |
| 생산 배수 | `1 + 채운슬롯 / 전체슬롯` (최대 2배) | 위키 |
| 전력 배수 | `(1 + 채운슬롯 / 전체슬롯)²` — 데이터의 `mProductionBoostPowerConsumptionExponent = 2` | 데이터 + 위키 |
| 합산 | `전력 = 기본전력 × 전력배수 × (클럭/100)^1.321929` | 위키 |

| ID | 요구 | 수준 |
|---|---|---|
| F13-37 | 소수 대수가 나오면 "올려 짓기 / 한 대 줄이고 오버클럭 / 언더클럭으로 정렬" 세 안을 전력·자재·면적으로 비교해 제시한다 | MUST |
| F13-38 | 파워 샤드 보유량을 입력받아, 실제로 가능한 오버클럭만 제안한다 | SHOULD |
| F13-39 | 소머슬룹 보유량을 입력받아 어디에 넣는 것이 이득인지 계산한다 (전력이 제곱으로 늘어나므로 항상 이득이 아니다) | SHOULD |
| F13-40 | 언더클럭으로 전력을 줄이는 안을 제시한다. 전력이 병목인 초반에는 이것이 정답인 경우가 있다 | SHOULD |
| F13-41 | 클럭·소머슬룹 변경이 기계 대수와 도면 크기에 미치는 영향을 도면에 즉시 반영한다 | MUST |

### 구현 우선순위

이 기능은 한 번에 완성되지 않는다. 아래 순서로 나누어 만들고, 각 단계는 그 자체로 쓸모가 있어야 한다.

| 단계 | 범위 | 성립 조건 |
|---|---|---|
| P1 | 단층 배치 생성 + 도면 SVG + 블루프린트 경계 검사 (F13-1~7, 15~20, 31~36) | 목표를 넣으면 지을 수 있는 단층 도면이 나온다 |
| P2 | 클럭·소머슬룹 최적화 (F13-37~41) | 대수 조정 대안이 수치로 비교된다 |
| P3 | 다층·물류 층·양정 검사 (F13-8~14) | 8m에 안 들어가는 건물이 있는 설계도 도면이 나온다 |
| P4 | 전력 설계 (F13-22~26) + 건설 순서 (F13-27~30) | 발전까지 포함한 완결된 설계가 나온다 |
| P5 | 장거리 물류 (F13-42~45) — **조사 선행 필요** | 거리에 맞는 운송 수단이 제시된다 |
| P6 | 공정 위치 추천 (F13-46~50) | 어느 노드 근처에 무엇을 지을지가 나온다 |
