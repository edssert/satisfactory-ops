# 전면 개편 실행 프로그램

이 문서는 저장소 전체 개편의 상태와 현재 실행 큐를 관리하는 유일한 정본이다. 기존 파일을 유지하는
계획이 아니라 제품 요구사항을 기준으로 소스·데이터·자산·문서를 `유지`, `재작성`, `합병`, `삭제`,
`신규` 중 하나로 판정한다.

## 1. 실행 통제

상태는 `대기`, `진행`, `검증`, `완료`만 사용한다. 구현 파일이 존재해도 요구사항별 자동 검증과 실제
브라우저·도면·데이터 증거가 없으면 완료가 아니다.

현재는 **연구·전환 인벤토리·검증형 구현 병행 단계**다. 대화 중 새 요구는 `PRODUCT`와 관련 기술 정본에
반영하고, 구현 큐는 근거·계약·자동 검증을 갖춘 항목부터 진행한다. 연구가 끝날 때까지 모든 구현을
동결하지 않으며, 반대로 파일이 존재한다는 이유만으로 완료 처리하지 않는다.

## 2. 변경 판정

| 판정 | 조건 |
|---|---|
| 유지 | 현재 구조가 요구사항과 데이터 계약을 충족하고 회귀 증거가 있음 |
| 재작성 | 사용자 과업은 유효하지만 구조·데이터·표현이 요구 수준에 미달 |
| 합병 | 동일 과업이나 데이터가 여러 라우트·컴포넌트에 중복됨 |
| 삭제 | 제품 과업에 기여하지 않거나 검증할 수 없는 구현·데이터·문서 |
| 신규 | 기존 구조로 표현할 수 없는 필수 과업·계약·검증 도구 |

구현 비용, 기간, 토큰, 유료 라이선스는 기술 점수에서 제외한다. 채택하지 않는 판단은
[[capability-evaluation-method-2026]]의 점수와 실제 파일럿 증거로만 한다.

## 4. 연구 프로그램

연구 문서는 출처 채널별로 만들지 않고 책임이 연결된 네 묶음으로 제한한다.

| 연구 묶음 | 범위 | 상태 | 필수 비교 대상 |
|---|---|---|---|
| [[capability-evaluation-method-2026]] | 전 기술·지식·스킬 평가 기준 | 검증 | 100점 점수표와 파일럿 규격 |
| 게임·생산·세이브 근거 | R-01, R-02, R-07 | 진행 | 설치본 Docs, 공식 자료, SCIM, Satisfactory Tools, Modeler, 실제 코퍼스, LP/MILP 후보 |
| 공장·기하·자산·도면 근거 | R-03, R-05, R-06, R-08 | 진행 | 시설 배치 논문·표준, Anders 원본, Figma, 실제 블루프린트, CAD·P&ID·도면 엔진 |
| 제품 인터페이스·품질 근거 | R-04, R-09~R-12 | 진행 | 실제 배포 편집기·지도·가이드·도감, 최신 저장소, 브라우저 표준, Codex 스킬 |

기존 [[architecture-evaluation-2026]]와 [[frontend-landing-technology-2026]]는 위 연구의 입력이지만 전체
기술 결론을 대신하지 않는다.

## 5. 제품 전환 인벤토리 범위

G-30은 다음 항목을 빠짐없이 판정한다.

| 범위 | 현재 확인된 대상 | 반드시 답할 질문 |

| 라우트 | `/`, guide, builder, recipes, tools, planner, map, checkup, dex, codex, tech, versions | 정식 과업은 무엇이며 무엇을 합병·삭제·리다이렉트하는가 |

## 7. 현재 실행 큐

개별 래스터 탑뷰 큐는 생성된 설계 대상 중 `requiresRasterTopview()`가 참인 고정 설비·장치 63건만
`unlockTier` 오름차순으로 처리한다. 같은 티어에서는 추출·전력, 생산, 물류, 저장 순이다. 토대 변형과
벨트·리프트·파이프·철도·높이 가변 지지대·경로 구멍·철도 신호는 임의 길이 경로를 설계판 합성 계약으로
그리되, Anders 시트에서 식별한 직선·90° 회전·방향·끝단·분기 역할은 모두 카탈로그에서 고를 수 있는
탑뷰 도구로 노출한다. Mk별 시각 차이는 현재 게임 용량·재질·형태 근거로 보존한다.

1. **완료** — AndersPottemager Satisfactory 원 게시물 21건·매체 42건을 색인하고 원본 37건을 해시 보관했다.
2. **배포 격리 완료·권리 확인 진행** — Anders 연구 대조 바이트를 `scripts/topview/references/`로 옮기고
   `reference-only`로 강등했다. `public/`·`dist/`·서비스워커에는 현재 게임 설치본 기반 `approved` 자산만
   exact allowlist로 허용한다. 원 게시물별 재배포·파생 조건 확인 전 외부 대조 자산은 앱에 포함하지 않는다.
3. **파일럿 재감사 진행** — FModel/CUE4Parse로 게임 1.2의 패키지 48,573건을 인덱싱하고
   정적·스켈레탈/VAT 메시·표시등·재질을 추출했다. Blender 5.2 LTS 프리셋과 채굴기·자동 바이오매스
   후보를 만들었다. 다음 조건은 CUE4Parse 의존성 보안 권고 해소와 복합 Anders 도면 시각 승인이다.
4. **벨트·파이프·리프트·철도 탑뷰 도구 완료** — Anders의 설계용 운송 역할을 카탈로그에서 직접 고를 수
   있도록 컨베이어·파이프·리프트·라이저·철도 도구를 노출한다. 게임 생성 데이터의 용량으로 목표 유량을 만족하는 최소 Mk를
   자동 선택하고, 벨트 슬랫 밀도·파이프 밴드·리프트 리브·수직 파이프 라이저로 Mk 차이를 형태와 텍스트에
   함께 표시한다. 실제 포트 끝점, 90° 회전, 경사, 높이, 저층/상층 가림, 방향, 유량/용량 라벨과 v4→v5
   저장 마이그레이션을 단위·브라우저 검사로 잠갔다. 철도는 자동 공간 배치 없이 사용자가 시작점·끝점을
   지정하는 자체 벡터 경로이며 선택 삭제·Undo/Redo·v6 저장·JSON·SVG/PNG 발행을 함께 지원한다.
5. **고정 설비 래스터 탑뷰 승격 재검증** — 기존 63건 집계는 파일 존재·카메라·점유 영수증은 통과했지만
   FactorySettings 포트 메시/재질, 저자 피벗, 활성 quaternion, 마스터 depth 속성을 검증하지 못했다.
   현재 승인 완료 주장을 철회하고 자동 바이오매스를 골든 fixture로 메인 파이프라인을 고친 뒤 낮은 티어부터
   부품·재질·포트·4방향 ISO를 다시 검수한다.
6. **그래프 엔지니어링 2차 기반 완료·Unreal probe→Blender 제품 렌더 전환 진행** — `FactoryGame/Content/` 23,057개 패키지와
   `CommunityResources/Headers.zip` API 심벌과 두 runtime probe를 154,346개 노드·269,036개 간선으로 연결했다.
   `port <BuildClass> <PortId>`가 FactorySettings→포트 메시/재질→저자 bounds→component transform→Headers API를
   compact JSON으로 반환하고 입력 해시 드리프트를 검사한다. Blender Cycles가
   `Hologram_Simple.bDisableDepthTest`의 native 배치와 실제 게임 재질·AbstractInstance/HISM·texture streaming을
   Unreal 5.6.1-CSS/SML 런타임 fixture로 확인했다. Unreal은 제품 이미지를 만들지 않고 최종 component transform,
   lightweight instance, MaterialInstance·텍스처, clearance, native 포트 메시·재질을 JSON probe로 그래프에 승격한다.
   제품 후보는 이 probe를 소비하는 하나의 Blender 장면에서 생성하며 포트는 정확한 3D 위치를 유지하되 자연 가림을
   허용한다. 바이오매스 연소기와 제작기의 토대 없는 2048px 탑뷰와 토대 포함 4방향 beauty ISO는 검증 후
   설계판·도감에 연결했다. technical ISO는 실제 BuildGun 상태의 viewport reference까지 확보했지만 cooked
   `Clearance`의 screen-space 선 폭·수직 감쇠를 Blender에서 아직 동일하게 실행하지 못해 차단 상태다. 이
   어댑터가 verified가 되고 두 기기의 technical 4방향이 통과할 때 이 단계를 완료한다.
7. **저장소 위생 정리 완료** — Blender가 만든 비ASCII 빈 캐시 폴더 16개와 루트 로그·임시 테스트 번들을
   제거하고, 렌더 캐시를 `.cache/blender-runtime/`으로 격리했다. 브라우저 증거는 `output/`의 목적별
   하위 폴더로 정리했으며 `check:hygiene`를 전체 검증 게이트에 추가했다.
8. 게임·생산·세이브 레퍼런스 제품과 알고리즘 후보를 수집하고 점수화한다.
9. 시설 배치·운송 기하·공정 도면의 원 논문·표준·실제 블루프린트를 수집한다.
10. 가이드·무한 캔버스·CAD·지도·도감·상태·내보내기·QA의 배포 제품과 최신 기술을 점수화한다.
11. R-01~12 결과를 검토해 G-20을 검증 상태로 이동한다.
12. 전체 저장소 전환 인벤토리와 완전 실행 계획을 작성한다.
13. **생산 계산→설계 인계 완료** — 복수 목표를 공용 중간재로 합산하고 부산물·보유 대체 제작법·기계·
    전력·벨트/파이프 Mk와 용량을 같은 결과에서 갱신한다. 선택된 재활용 순환은 순생산 연립방정식으로
    풀며 특이·음수 해를 거부한다. 설비·레시피·클럭·대수·목표 유량은 버전 1 대기열로 설계판에 전달하고,
    사용자가 한 대씩 위치를 정하면 잔량이 감소한다. SVG/PNG는 64px/m 축척과 Mk·유량·용량·깊이 범례를
    포함한다.
14. **세이브 해석·공장 진단 완료** — `.sav` 파서·공장 모델·진단을 파일 선택 뒤 생성되는 Worker로
    격리하고 파일 바이트를 브라우저 밖으로 보내지 않는다. 실제 골든 세이브에서 설비 43대·평균 가동률
    82%·진단 10건을 화면까지 렌더했으며, 전력 부족·가동률·굶음/막힘·끊긴 출력·재고·위험 지점과 수정
    위치를 29개 결정적 진단 테스트와 독립 참조 구현으로 검증한다. 지원하지 않는 버전·손상 파일은 원인을
    명시하고 원본을 변경하지 않는다.
15. **로컬 release 검증 완료** — 전체 단위 테스트, 80개 정적 라우트, WCAG 2.2 AA 30개 렌더,
    9개 핵심 도메인×7개 폭, no-JS·테마·모션·가이드·플래너 실제 조작, SVG/PNG 다운로드, 서비스워커

## 8. 스트림 완료 조건

앱 구현·배포와 장기 연구 프로그램의 종료 조건을 분리한다. 이미 PRODUCT 완료 증거를 통과한 기능은
R-01~12 전수 연구를 기다리지 않고 배포할 수 있다. G-20 연구 완료를 주장할 때만 첫 두 항목을 요구한다.

- G-20 완료 시 R-01~12에 공식·원본 근거, 최신 지표, 점수와 실제 파일럿 계획이 있음
- G-20 완료 시 고별·활성 저장소와 실제 배포 제품을 임의로 제외하지 않았음
- 모든 기존 파일군에 변경 판정이 있음
- PRODUCT의 모든 ID가 구현 작업과 검증 증거에 연결됨
- 삭제·합병 대상의 데이터·URL·사용자 상태 마이그레이션이 정의됨
- 전체 검증, 배포, 오프라인, 롤백 순서가 정의됨
