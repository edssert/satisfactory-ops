# 자산 기술 규격

## 1. 범위

기계, 물류 장치, 토대, 아이템, 지도와 랜딩 장면에 사용하는 게임 연관 자산의 식별, 출처, 파생 과정,
축척과 승인 상태를 관리한다.

## 2. 디렉터리

```text
public/assets/
├─ planner/
│  ├─ top-view/buildings/
│  ├─ top-view/logistics/
│  ├─ foundations/
│  └─ transport/
├─ items/
├─ map/
└─ brand/
```

파일명은 원본 클래스 또는 안정적인 내부 식별자에서 파생한다. `final`, `new`, `fixed`, 제작자 이름 같은
상태 문자열을 파일명에 넣지 않는다. 출처와 승인 상태는 매니페스트에서 관리한다.

Anders 원본 시트의 전수 후보 정본은 `src/data/curated/anders-topview-candidates.json`이다. 모든 후보는
`<sheet>#<candidateId>` 안정 ID, 감지 박스, 식별 상태, 클래스·역할, 신뢰도, 출처, 미해결 질문을 가진다.
`topview-assets.json`에는 이 후보 중 실제 크롭·축척·시각 승인을 받은 런타임 자산만 등록한다.

완성 도면 문맥 색인은 `src/data/curated/anders-layout-corpus.json`이다. 출처, 원본·축소본 SHA-256,
픽셀 크기, 제작자, 분석 대상을 분리해 기록하고 자산 그룹이 실제 기계·벨트·파이프·리프트 흐름에서
어떻게 쓰이는지 역인덱스로 연결한다. 원 게시물과 재배포 조건이 확인되기 전 원본 도면 이미지는
저장소에 커밋하지 않는다.

Anders의 공개 Reddit 원출처 전수 색인은 `src/data/curated/anders-reddit-posts.json`이다. 게시물 21건과
매체 42건의 원 URL·픽셀 크기·해시·확보 상태를 기록하며 이미지 바이트는 배포하지 않는다. 접근 가능한
원본 37건은 연구 보관소에 보존했고 삭제된 게시물 매체 5건은 `unavailable`로 남겼다.

## 3. 탑뷰 계약

각 자산은 다음 정보를 가져야 한다.

- 원본 클래스와 표시 역할
- 파일 경로, 픽셀 크기, 투명 영역 크롭 박스
- 실제 점유 박스와 시각 자산 박스
- 회전 원점과 기본 방향
- 포트 좌표·방향·매체
- 출처, 라이선스 또는 사용 근거, 파생 과정
- 시각 프로파일과 승인 상태

모든 기계 탑뷰는 Anders 자산과 같은 흰색 `ㄴ`형 설치 범위 코너 네 개를 포함한다. 코너 안쪽 사각형은
게임 하드 클리어런스 XY 합집합과 `occupancyFrame`에 일치해야 한다. 누락 자산을 게임 메시로 새로
렌더할 때도 Anders 원본 코너 조각의 두께·길이·그림자·안쪽 여백을 정규화해 사용한다. 코너가 없거나
점유 프레임과 어긋난 자산은 구조 검증을 통과하지 못한다.

이미지의 투명 여백으로 실제 점유 크기를 표현하지 않는다. AndersPottemager 계열 자산, 게임 메시 렌더,
공식 이미지 크롭은 시각 프로파일이 다르므로 동일 화면에 혼용하기 전에 밝기, 시점, 그림자, 외곽선,
해상도 기준을 통과해야 한다.

플래너는 평상시 자산의 흰 설치 코너를 보여 준다. 선택·충돌·배치 대기 상태만 별도 의미색 오버레이를
추가하며, 같은 위치에 상시 사각 테두리를 중복 표시하지 않는다.

## 4. 토대와 운송 자산

토대 타일은 인접 배치 시 외곽 프레임만 자연스럽게 이어지고 중앙에 흰 선이나 이중 경계가 생기지 않아야
한다. 벨트·파이프·리프트는 정적인 장식 선이 아니라 실제 경로 부품이며, 방향·굽힘·높이·깊이와 흐름
표시를 렌더 모델에서 계산한다.

## 5. 생성형 도구 사용

게임과 무관한 대체 기계나 공장 장면을 생성하지 않는다. 생성형 도구는 검증 가능한 원본 메시·스크린샷을
기반으로 한 재질 후보, 배경 제거, 해상도 보정, 시각 프로파일 탐색에만 사용하고 결과를 원본과 대조한다.

## 6. 누락 탑뷰 렌더 파이프라인

Anders가 공개한 제작 원리는 `게임 자산 추출 → glTF → Blender → 사용자 정의 재질·장면 → 투명 탑뷰
렌더`다. 현재 게임 버전에 적용할 기준 파이프라인은 다음과 같다.

1. 현재 게임의 UE5 아카이브는 FModel/CUE4Parse 파일럿으로 정적 메시, 스켈레탈·애니메이션 메시,
   재질 인스턴스와 텍스처를 추출한다. 구버전 UModel 명령을 현재 버전에 그대로 적용하지 않는다.
2. 한 건물을 이루는 정적·애니메이션 메시와 별도 생산 표시등을 클래스별 컬렉션으로 조합한다.
3. Blender의 정사영 카메라, 고정 회전 원점, 투명 필름, 동일 렌더 크기를 프리셋으로 잠근다.
4. Anders가 설명한 무광·발광 재질 원리를 기준으로 Albedo, AO, Facing, Metallic, Emission을 조합한다.
   물리 조명을 임의로 추가해 시트마다 그림자가 달라지게 하지 않는다.
5. Anders 원본의 흰 `ㄴ`형 점유 코너를 게임 하드 박스에 맞춰 합성한다.
6. 원본 19개 자산과 동일 화면에 배치해 시점·실루엣·재질·발광·그림자·점유 코너를 승인한 뒤에만
   `candidate`에서 `approved`로 승격한다.

## 7. 승인 기준

구조 검증과 시각 승인을 분리한다. 경로·크기·출처·식별자가 유효해도 시점과 그림체가 다른 자산은 후보로
남긴다. 전체 기기 탑뷰가 동일 프로파일로 검수되고 복합 공정에서 실제 축척으로 합성될 때만 완성으로 본다.

현재 Anders 시트에서 검출한 픽셀 연결 성분은 91건이고, 흰 점유 코너를 본체에 결합한 의미 자산 그룹은
84건이다. 그룹 중 19건은 런타임 자산과 연결됐고, 14건은 게임 클래스를 식별했으며, 20건은 운송 부품
등의 역할을 식별했다. 이 집계는 서로 겹칠 수 있으며 31건은 아직 미식별이다. 미식별 그룹을 추측으로
런타임 자산에 승격하지 않는다.
컨베이어 리프트는 `Texture 02.png#21`과 `#33`의 독립 탑뷰 변형을 사용한다. Mk.1~6은 공통 탑뷰를
재사용하고, 높이는 이미지 길이가 아니라 Z 값·라벨·레이어 가림 순서로 표현한다.
