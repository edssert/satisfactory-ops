# 자산 기술 규격

## 1. 범위

기계, 물류 장치, 토대, 아이템, 지도와 랜딩 장면에 사용하는 게임 연관 자산의 식별, 출처, 파생 과정,
축척과 승인 상태를 관리한다.

## 2. 디렉터리

```text
public/assets/
├─ planner/
│  ├─ top-view/buildings/
│  ├─ top-view/logistics/
│  ├─ foundations/
│  └─ transport/
├─ items/
├─ map/
└─ brand/
```

파일명은 원본 클래스 또는 안정적인 내부 식별자에서 파생한다. `final`, `new`, `fixed`, 제작자 이름 같은
상태 문자열을 파일명에 넣지 않는다. 출처와 승인 상태는 매니페스트에서 관리한다.

Anders 원본 시트의 전수 후보 정본은 `src/data/curated/anders-topview-candidates.json`이다. 모든 후보는
`<sheet>#<candidateId>` 안정 ID, 감지 박스, 식별 상태, 클래스·역할, 신뢰도, 출처, 미해결 질문을 가진다.
`topview-assets.json`에는 이 후보 중 실제 크롭·축척·시각 승인을 받은 런타임 자산만 등록한다.

완성 도면 문맥 색인은 `src/data/curated/anders-layout-corpus.json`이다. 출처, 원본·축소본 SHA-256,
픽셀 크기, 제작자, 분석 대상을 분리해 기록하고 자산 그룹이 실제 기계·벨트·파이프·리프트 흐름에서
어떻게 쓰이는지 역인덱스로 연결한다. 원 게시물과 재배포 조건이 확인되기 전 원본 도면 이미지는
저장소에 커밋하지 않는다.

Anders의 공개 Reddit 원출처 전수 색인은 `src/data/curated/anders-reddit-posts.json`이다. 게시물 21건과
매체 42건의 원 URL·픽셀 크기·해시·확보 상태를 기록하며 이미지 바이트는 배포하지 않는다. 접근 가능한
원본 37건은 연구 보관소에 보존했고 삭제된 게시물 매체 5건은 `unavailable`로 남겼다.

## 3. 탑뷰 계약

각 자산은 다음 정보를 가져야 한다.

- 원본 클래스와 표시 역할
- 파일 경로, 픽셀 크기, 투명 영역 크롭 박스
- 실제 점유 박스와 시각 자산 박스
- 회전 원점과 기본 방향
- 포트 좌표·방향·매체
- 출처, 라이선스 또는 사용 근거, 파생 과정
- 시각 프로파일과 승인 상태

모든 기계 탑뷰는 Anders 자산과 같은 흰색 `ㄴ`형 설치 범위 코너 네 개를 포함한다. 코너 안쪽 사각형은
게임 하드 클리어런스 XY 합집합과 `occupancyFrame`에 일치해야 한다. 누락 자산을 게임 메시로 새로
렌더할 때도 Anders 원본 코너 조각의 두께·길이·그림자·안쪽 여백을 정규화해 사용한다. 코너가 없거나
점유 프레임과 어긋난 자산은 구조 검증을 통과하지 못한다.

이미지의 투명 여백으로 실제 점유 크기를 표현하지 않는다. AndersPottemager 계열 자산, 게임 메시 렌더,
공식 이미지 크롭은 시각 프로파일이 다르므로 동일 화면에 혼용하기 전에 밝기, 시점, 그림자, 외곽선,
해상도 기준을 통과해야 한다.

플래너는 평상시 자산의 흰 설치 코너를 보여 준다. 선택·충돌·배치 대기 상태만 별도 의미색 오버레이를
추가하며, 같은 위치에 상시 사각 테두리를 중복 표시하지 않는다.

## 4. 토대와 운송 자산

토대 타일은 인접 배치 시 외곽 프레임만 자연스럽게 이어지고 중앙에 흰 선이나 이중 경계가 생기지 않아야
한다. 벨트·파이프·리프트는 정적인 장식 선이 아니라 실제 경로 부품이며, 방향·굽힘·높이·깊이와 흐름
표시를 렌더 모델에서 계산한다.

## 5. 생성형 도구 사용

게임과 무관한 대체 기계나 공장 장면을 생성하지 않는다. 생성형 도구는 검증 가능한 원본 메시·스크린샷을
기반으로 한 재질 후보, 배경 제거, 해상도 보정, 시각 프로파일 탐색에만 사용하고 결과를 원본과 대조한다.

## 6. 누락 탑뷰 렌더 파이프라인

Anders가 공개한 제작 원리는 `게임 자산 추출 → glTF → Blender → 사용자 정의 재질·장면 → 투명 탑뷰
렌더`다. 현재 게임 버전에 적용할 기준 파이프라인은 다음과 같다.

1. CUE4Parse로 `Buildable`, 공용 재질·텍스처, `MasterMaterials`, VAT 원본을 전수 색인한다. 현재 기준은
   6,706개 패키지, 재질 901개, 구성품 3,809개, 참조 54,868개이며 실패 패키지는 0개다.
2. 색인에서 576개 `Build_*` Blueprint 장면 계약을 생성한다. 정적·VAT·생산 표시등 같은 시각 구성품과
   사다리 상호작용·입출력·전력 연결 같은 비시각 구성품을 분리한다.
3. 현재 Blueprint가 참조하는 메시와 CDO 변환만 장면 레시피에 넣는다. 제련기는 현재형
   `SM_VAT_Smelter_01`, `SmelterMk1_static`, 간접 생산 표시등을 사용하며 구형 `SK_SmelterMk1`은
   연구 대조군일 뿐 제품 렌더에 사용하지 않는다.
4. 재질 부모 체인을 루트까지 해석하고 Texture2DArray의 모든 슬라이스를 추출한다. 조립 검수는 원본
   PBR 채널과 중립 키·필 라이트로 모든 부품을 확인한다. Anders식 무조명·Facing 스타일은 조립과 재질
   완전성 검사를 통과한 뒤 별도 출력 프로파일로 적용한다.
5. Blender의 수직 정사영 카메라(`frontTiltDeg=0`), 고정 회전 원점, 투명 필름, 동일 렌더 크기를 잠근다.
   사선 평행투영은 Anders 연구 비교 전용이며 런타임 탑뷰에 사용하지 않는다.
6. Anders 원본의 흰 `ㄴ`형 점유 코너를 게임 하드 박스의 정사영 외곽에 합성한다.
7. 원본 19개 자산과 동일 화면에 배치해 시점·실루엣·재질·발광·그림자·점유 코너를 승인한 뒤에만
   `candidate`에서 `approved`로 승격한다.

현재 재현 기준은 FModel `7c86ee47`/CUE4Parse `7afcbb32`, Blender 5.2.0 LTS다. Blender 단계는
`scripts/topview/render-topview.py`로 실행하며 다음 계약을 갖는다.

- `--scene`은 전수 게임 자산 그래프와 일치 검사를 통과한 클래스별 장면 레시피다. 수동 `--glb` 나열은
  격리 진단에만 사용한다.
- 현재 CUE4Parse glTF 좌표 계약에서 Unreal 상대 좌표는 Blender `(-X,Y,Z)`와 반전된 yaw로 변환한다.
- `--footprint`과 `--footprint-center`는 시각 메시 크기가 아니라 게임 하드 클리어런스 XY 합집합이다.
- 텍스처가 있는 재질은 `--material-albedo`와 `--material-ao`로 복원하고, 실제 재질의 발광 설정이
  확인된 부분만 `--material-emissive-accent`로 강화한다.
- PNG와 `.blend`를 함께 만들며, 배포 WebP의 SHA-256과 정규화된 `occupancyFrame`은
  `topview-assets.json`에 기록한다.

전수 색인은 `.cache/game-asset-index/factory-assets.ndjson`, 자동 장면 계약은
`.cache/game-asset-index/factory-scenes.json`에 생성한다. `scripts/game-assets/query-factory-assets.mjs`는
건물 구성품과 재질 부모 체인을 질의하고, `check-factory-assets.mjs`와 `check-scene-recipe.mjs`는 제련기
필수 구성품·VAT 루트 재질·CDO 변환을 검사한다. 생성 캐시는 커밋하지 않는다.

채굴기 Mk.1과 자동화 바이오매스 연소기는 이 파이프라인으로 교체됐지만 아직 `candidate`다. 구조 검사는
파일 SHA-256, 양수 실축, 0~1 범위 점유 프레임을 확인한다. Blender 설치와 렌더 성공만으로 시각 승인을
대체하지 않는다.

## 7. 승인 기준

구조 검증과 시각 승인을 분리한다. 경로·크기·출처·식별자가 유효해도 시점과 그림체가 다른 자산은 후보로
남긴다. 전체 기기 탑뷰가 동일 프로파일로 검수되고 복합 공정에서 실제 축척으로 합성될 때만 완성으로 본다.

누락 자산의 렌더 파라미터를 임의로 조정하기 전에 원 제작자 게시물·댓글·배포 파일, 게임 공용 재질과
유사 Blender 구현을 먼저 조사한다. 제련기 한 건을 골든 마스터로 사용해 재질 셀, 발광, AO 그림자,
카메라와 코너를 확정하며, 이 기준을 통과하기 전에는 다른 기기를 양산하지 않는다. 목표 방식과 다른
실험 코드는 제품 파이프라인에 남기지 않고 실패 이유를 Research에 기록한다.

현재 Anders 시트에서 검출한 픽셀 연결 성분은 91건이고, 흰 점유 코너를 본체에 결합한 의미 자산 그룹은
84건이다. 그룹 중 19건은 런타임 자산과 연결됐고, 14건은 게임 클래스를 식별했으며, 20건은 운송 부품
등의 역할을 식별했다. 이 집계는 서로 겹칠 수 있으며 31건은 아직 미식별이다. 미식별 그룹을 추측으로
런타임 자산에 승격하지 않는다.
컨베이어 리프트는 `Texture 02.png#21`과 `#33`의 독립 탑뷰 변형을 사용한다. Mk.1~6은 공통 탑뷰를
재사용하고, 높이는 이미지 길이가 아니라 Z 값·라벨·레이어 가림 순서로 표현한다.
