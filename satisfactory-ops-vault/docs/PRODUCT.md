# 제품 요구사항

## 1. 제품 정의

Satisfactory Ops는 Satisfactory 공장을 계산하고, 실제 크기로 배치하고, 물류를 연결하고, 시공 가능한
도면으로 내보내는 브라우저 애플리케이션이다. 가이드, 계산기, 설계 스튜디오, 게임 데이터 도감은 별도
제품이 아니라 동일 게임 모델을 공유하는 작업 흐름이다.

```text
게임 데이터와 사용자 진행
  → 생산 목표와 제약 계산
  → 설비·레시피 구성
  → 실제 축척 수동 배치
  → 벨트·파이프·리프트 연결
  → 충돌·처리량·방향·높이 검증
  → 시공용 SVG/PNG 도면
```

## 2. 제품 원칙

1. 계산기는 부가 기능이 아니다. SCIM과 동급 이상의 탐색성과 더 명확한 한국어 UI를 제공해야 한다.
2. 자동 공간 배치는 제공하지 않는다. 계산 결과는 배치 대기열로 전달하고 최종 배치는 사용자가 통제한다.
3. 게임 수치, 치수, 포트, 제작법은 검증된 데이터에서만 가져온다. 기억이나 임시 상수로 채우지 않는다.
4. 탑뷰, 점유 영역, 운송 경로, 내보낸 도면은 하나의 좌표·축척·깊이 모델을 공유한다.
5. 랜딩은 장식용 공장 이미지를 보여 주지 않는다. 실제 앱 데이터와 렌더러가 만드는 공정을 제품 증거로 쓴다.
6. 사용자 세이브와 설계 데이터는 브라우저 밖으로 전송하지 않는다.

## 3. 기능 요구사항

| ID | 요구사항 | 승인 조건 |
|---|---|---|
| PROD-01 | 목표 품목과 분당 생산량으로 전체 생산망을 계산한다 | 복수 목표, 중간재, 부산물, 순환, 벨트·파이프 한계와 BOM을 동일 결과에서 추적한다 |
| PROD-02 | 기본·대체 제작법을 검색·비교·선택한다 | 해금 조건, 원료, 설비, 전력, 부산물과 선택 영향을 즉시 비교한다 |
| PROD-03 | 설비별 클럭, 파워 샤드, 소머슬룹을 설정한다 | 입력·출력·전력·설비 수가 게임 규칙에 따라 재계산된다 |
| PROD-04 | 계산 결과를 설계 대기열로 넘긴다 | 설비·제작법·클럭·목표 유량은 유지하되 공간 위치는 사용자가 결정한다 |
| PLAN-01 | 카탈로그에서 드래그하거나 선택 후 캔버스를 클릭해 설비와 토대를 놓는다 | 임의 위치에 자동 생성하는 추가 버튼이 없다 |
| PLAN-02 | 기계의 실제 점유 영역과 탑뷰 이미지 영역을 분리한다 | 회전 후에도 점유 프레임과 이미지가 정확히 일치하고 인접 프레임은 여백 없이 맞닿는다 |
| PLAN-03 | 실제 토대 이미지를 타일로 배치한다 | 인접 토대 사이에 흰 선이나 이중 테두리가 생기지 않는다 |
| PLAN-04 | 벨트·파이프·리프트를 실제 포트 사이에 연결한다 | 최소 길이, 굽힘, 방향, 높이와 용량을 검증하고 상부 요소가 하부 요소를 올바르게 가린다 |
| PLAN-05 | 선택·이동·회전·복제·삭제를 전문 편집기 수준으로 제공한다 | 배경 팬, 줌, 영역 선택, Ctrl+C/V, 다중 삭제, 초기화, Undo/Redo가 동작한다 |
| PLAN-06 | 배치 대기 프리뷰를 최상위 편집 레이어에 표시한다 | 토대나 기존 설비 아래로 가려지지 않고 충돌·스냅 상태가 즉시 보인다 |
| PLAN-07 | 라벨과 포트 표시를 판독 가능하게 한다 | 기계 회전 시 텍스트는 회전하지 않으며 병합기·분배기는 자체 방향 표식으로 구분하고 포트 배지는 필요할 때만 노출한다 |
| PLAN-08 | 전력망 데이터·도감·전력 계산은 유지하되 전선 경로 편집만 제외한다 | 전선·전신주·스위치는 게임 데이터와 도감·전력 모델에 남고, 설계판은 연결된 것으로 간주해 경로·탑뷰 배치를 요구하지 않는다 |
| PLAN-09 | 고품질 시공 도면을 내보낸다 | SVG/PNG가 실제 축척, 토대, 기계, 운송 경로, 흐름 방향, 처리량, 범례를 유지한다 |
| DATA-01 | 게임 설치 데이터와 한국어 로케일을 정본으로 사용한다 | 모든 표시명과 수치의 원본 클래스·버전·출처를 역추적할 수 있다 |
| DATA-02 | 공개 세이브·블루프린트로 모델을 교차 검증한다 | 라이선스·버전·출처가 확인된 표본만 검증 코퍼스에 포함한다 |
| ASSET-01 | 설계 가능한 모든 기계·물류 장치·토대의 탑뷰 또는 경로 표현을 제공한다 | 고정 설비는 아이콘 대체 없이 단일 시각 프로파일·실제 축척·점유 프레임을 충족하고, 가변 물류는 Mk별 합성 계약을 가지며, 자동 연결 전력망은 도감·전력 모델에서 빠지지 않는다 |
| STATE-01 | 계산·설계·진행 상태를 버전이 있는 브라우저 데이터로 저장한다 | 마이그레이션·복구·초기화·JSON 가져오기/내보내기를 검증하고 실패 시 원본을 보존한다 |
| SAVE-01 | 사용자 `.sav`를 브라우저에서 해석한다 | 외부 전송 없이 진행, 설비, 좌표와 연결을 읽고 지원하지 않는 버전은 명시적으로 거부한다 |
| CHECK-01 | 세이브와 설계 상태를 공정 모델로 진단한다 | 가동률·입출력·용량·지지·연결 문제를 근거와 수정 위치까지 추적한다 |
| MAP-01 | 자원 노드·시작 지점·사용자 진행을 지도에서 탐색한다 | 필터·검색·범례·좌표·저장 상태가 키보드와 터치에서 동작하고 출처가 추적된다 |
| DEX-01 | 아이템·제작법·설비·마일스톤·MAM·상점을 한 데이터 탐색 경험으로 제공한다 | 검색·필터·상호 링크·해금 경로가 중복 라우트 없이 동일 식별자를 사용한다 |
| LAND-01 | 실제 제품을 보여 주는 랜딩을 제공한다 | 동일 공장 모델이 목표→계산→배치→라우팅→검증→도면 상태로 전환된다 |
| LAND-02 | 스크롤 기반 장면과 페이지 전환을 제공한다 | 역스크롤·중간 진입·축소 모션·키보드·정적 폴백을 모두 검증한다 |
| GUIDE-01 | 사용자의 현재 진행에서 다음 행동을 제안한다 | 게임 사실과 전략 판단을 분리하고 출처와 이견을 표시한다 |
| IA-01 | 사용자 과업마다 하나의 정식 진입 경로를 제공한다 | 중복·시험·이전 라우트는 합병 또는 삭제하고 필요한 이전 URL만 명시적으로 리다이렉트한다 |

## 4. 품질 요구사항

| ID | 기준 |
|---|---|
| QUAL-01 | WCAG 2.2 AA, 키보드 전체 과업, 200% 확대, 축소 모션을 지원한다 |
| QUAL-02 | 375·768·1024·1440·3840px에서 랜딩·계산기·설계판을 실제 렌더로 검증한다 |
| QUAL-03 | 편집기 상호작용 중 긴 작업은 Worker로 격리하고 팬·줌·드래그의 프레임 안정성을 측정한다 |
| QUAL-04 | 게임 사실은 출처, 접근일, 게임 버전과 신뢰도를 가진다 |
| QUAL-05 | 핵심 값과 CTA는 애니메이션이나 JavaScript가 실패해도 읽을 수 있다 |
| QUAL-06 | 공개 배포는 직접 경로, 새로고침, 서비스워커와 오프라인 동작을 검증한다 |

## 5. 범위 제외

- 공장 공간 배치를 임의로 결정하는 자동 배치
- 전선과 전봇대의 도면 배치(게임 데이터·도감·전력 계산·해금 정보는 제외하지 않음)
- 게임사 공식 제품으로 오인시키는 브랜딩
- 검증되지 않은 생성형 이미지로 게임 자산을 대체하는 작업

## 6. 완료 정의

기능 완료는 코드 존재가 아니라 실제 브라우저 조작, 자동 검증, 대표 공정 도면의 시각 판정, 공개 배포에서
재현 가능한 증거가 모두 있을 때만 인정한다.
