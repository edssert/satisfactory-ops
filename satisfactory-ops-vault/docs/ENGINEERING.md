# 시스템 기술 규격

## 1. 현재 결정

Astro를 문서·정적 라우트·빌드타임 데이터 전달 셸로 사용하고, Preact를 계산기·설계판·지도·세이브 진단의
라우트 단위 사용자 작업 공간에 사용한다. 이는 기존 구현을 보존하기 위한 결정이 아니다. 전환 비용을
평가에서 제외하고 Astro, SvelteKit, React Router, Next.js, Vite+Preact를 다시 비교한 결과다.

Astro 유지 조건과 재평가 근거는 [[architecture-evaluation-2026]]에 기록한다. 기존의 “상태를 소유하는 최소
컴포넌트만 아일랜드” 규칙은 폐기한다. 캔버스·선택·클립보드·Undo/Redo·속성 편집기가 강하게 결합된
설계판은 하나의 작업 공간이어야 한다.

## 2. 시스템 경계

```text
게임 설치본 Docs + 검증된 수기 근거
  → 정규화 및 로케일 결합
  → 버전이 명시된 앱 데이터
  → Astro 정적 HTML/라우트 페이로드
  → Preact 작업 공간 + Worker
  → 브라우저 저장소 + 독립 SVG/PNG
```

- 서버 데이터베이스와 사용자 업로드 API는 두지 않는다.
- 원본 게임 데이터는 빌드타임에만 해석한다.
- 브라우저에는 라우트별 최소 데이터만 props, 정적 페이로드 또는 Worker 청크로 전달한다.
- 사용자 상태와 세이브 내용은 외부로 전송하지 않는다.

## 3. 모듈 소유권

| 모듈 | 책임 |
|---|---|
| `src/data/` | 게임 원본의 정규화 산출물과 검증된 수기 데이터 |
| `src/domain/production/` | 제작법 그래프, 유리수 계산, 순환·부산물·용량·전력 해석 |
| `src/domain/factory/` | 좌표, 점유 영역, 포트, 운송 기하, 깊이, 충돌, 도면 모델 |
| `src/components/ProductionStudio*` | 계산기 사용자 작업 공간 |
| `src/components/ValidatedFactoryPlanner*` | 설계판 사용자 작업 공간 |
| `src/workers/` | 세이브 파싱, 대형 그래프 계산, 고비용 공간 검증 |
| `src/state/` | 버전이 있는 사용자 상태, 마이그레이션, 복구 |
| `src/pages/` | 정적 라우트와 작업 공간 데이터 경계 |

## 4. 핵심 데이터 계약

모든 게임 객체는 표시명 대신 안정적인 원본 클래스 식별자로 연결한다. 표시명은 공식 로케일에서 파생한다.
설비 스펙은 최소한 실제 점유 박스, 시각 자산 박스, 회전 원점, 높이, 포트 좌표·방향·매체, 제작법 허용
범위와 전력 모델을 가져야 한다.

공장 편집 상태는 게임 스펙 전체를 복제하지 않고 식별자, 좌표, 회전, 높이, 선택 제작법과 클럭 설정만
저장한다. 로드 시 현재 버전의 검증된 스펙과 재결합하고 스키마 마이그레이션을 수행한다.

## 5. 렌더 및 깊이 모델

좌표 단위는 미터다. 화면 배율은 렌더 단계에서만 적용한다. 점유 영역, 이미지, 포트, 경로, 선택 프레임은
같은 월드 변환을 사용한다. SVG 레이어는 토대, 하부 운송, 설비, 상부 운송·리프트, 선택·포트, 검증,
배치 프리뷰 순으로 관리한다. 텍스트는 별도 화면 좌표 레이어에 두어 설비 회전의 영향을 받지 않는다.

## 6. 데이터 신뢰 정책

기존 Claude 조사 노트와 크롤링 결과는 근거로 사용하지 않는다. 게임 설치본, 공식 문서, 원본 저장소,
논문·표준, 라이선스가 확인된 공개 세이브·블루프린트를 다시 조사한다. 검증 전 필드는 UI나 알고리즘의
상수로 승격하지 않는다.

## 7. 검증 게이트

1. 데이터 생성물 드리프트와 외래키 검증
2. 생산식·기하·라우팅·직렬화 단위 및 속성 기반 테스트
3. TypeScript와 빌드 검증
4. 문서 링크·허용 속성·출처 검증
5. 접근성, 축소 모션, no-JS, 반응형 브라우저 검증
6. 실제 도면의 축척·겹침·토대 이음·흐름·깊이 시각 판정

## 8. 테스트·개발 서버 메모리 안전

- `npm test`는 Node 힙을 1GB로 제한한다. 회귀 루프가 생겨도 시스템 커밋 한도까지 확장시키지 않는다.
- Preact DOM 테스트는 `preact/test-utils`의 `act()`로 렌더와 이벤트를 배칭한다. `options.debounceRendering`을
  완전 동기 콜백으로 덮어쓰지 않는다. 이 설정은 effect 정리 순서를 깨뜨려 키보드 이벤트 뒤 무한
  재렌더와 60GB 이상 커밋을 일으킨 전례가 있다.
- happy-dom 테스트의 ResizeObserver는 결정적 테스트 대역을 사용한다. 실제 크기·포커스·스크롤·반응형
  동작은 Chromium 접근성·반응형 검증이 담당한다.
- 실제 ResizeObserver 콜백은 같은 크기 값을 다시 상태에 쓰지 않는다.
- Astro 개발 서버는 Windows 파일 감시 때문에 약 1GB의 Private Bytes와 다수 핸들을 예약할 수 있다.
  화면 작업 중에만 실행하고 장시간 연구·데이터 작업이나 전체 검증 전에는 `npx astro dev stop`으로 끈다.
- headed Playwright 데몬을 상주시킨 채 두지 않는다. 모든 브라우저 검증은 종료 시 context, browser와 로컬
  HTTP 서버를 `finally`에서 닫는다.

## 9. 재평가 조건

Astro가 작업 공간 청크 분리, Worker, 전환, 오프라인 배포 또는 테스트를 방해하거나, SvelteKit·React
Router 등 대안이 동일한 정적 전달 품질에서 작업 공간 복잡도를 유의하게 낮추면 프레임워크를 다시 평가한다.
